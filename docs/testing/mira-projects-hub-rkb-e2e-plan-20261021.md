Он не доказывает deployment. Pending/continuation и model-visible media через PH ещё нужно подтвердить; несовместимость — **BLOCKED**, не пустой успешный ответ. Не изобретать новый endpoint/tool.
2. RKB-владелец подтверждает выбранный target PG/BGE warm worker, corpus/revisions, READY, существующие verified person links и target-scoped service authorization. Owner и non-owner проверяются раздельно; PH bearer/actor ID не превращаются в RKB права. Тестовый runner не выдаёт grants и не включает receiver сам.
3. Назначить один execution owner на согласованные SHA/конфигурацию, бюджет provider calls, allowed effects и cleanup только своих ресурсов. Сначала выбрать runner отдельно: локальный Dev имеет 4 GB; без тяжёлых fixtures, локального BGE и установки emulator по умолчанию. Android host/KVM/Actions и paired backend выбираются по текущей доступности, не по старым receipts.
4. Подготовить маленький versioned seed из уже существующих held-out families/разрешённых источников: stable case IDs, вопросы (текст + короткое аудио), exact source/page/revision/Variant/figure refs, ожидаемые факты и запрещённые выводы. Подготовка/withdraw/revoke выполняются отдельно в isolated fixture, не внутри обычного чтения и не в canonical corpus. Нет второй огромной benchmark-базы.

## 4. Порядок, oracle и доказательства
**Позже:** (A) source/config readiness и согласование недостающего wiring; (B) малые deterministic contract проверки; (C) headless real text, затем buffered audio; (D) Android controlled baseline, затем тот же seed через реальный provider; (E) затронутые concurrency/maintenance и paired Mira/Dot сценарии §14.4. Dot остаётся независимым клиентом, не дополнительным шагом Миры. Без prerequisites этап остаётся BLOCKED/NOT RUN.

Один correlated trace: case/run → conversation/source/utterance + provider transcript → capability/tool call/request/generation → RKB admission/worker → evidence dependencies/revisions → tool result → spoken/text answer и playback. Записать per-host monotonic durations: capture/checkpoint, capability activation, tool-lock/queue wait, admission, encode, lexical/ANN/fusion/hydrate, serialization/validation, model/output transport/playback. Межхостовые clocks не вычитать; p95 стадий не складывать.

Главные метрики: конец высказывания → первый **полезный source-grounded слышимый** ответ и → полный ответ; отдельно tool start→usable evidence. Headless без playback не утверждает слышимую задержку. «Сейчас посмотрю» не полезный ответ. Protected backend/MCP/evidence gates **1000/1500/2000 ms** и representative-load/quality gates остаются неизменными; маленький seed их не закрывает. Cold startup измеряется отдельно. Указать выборку/повторы/percentile method; учитывать все timeout/cancel/degraded/denied, не только удачи.

Oracle реальной модели — source-grounded rubric: точность фактов, достаточность, exact attribution/refs, сохранённые uncertainty/conflict/body, отсутствие unsupported claims и утечек. Не exact-string ответ и не обязательный второй LLM-судья. Детерминированные IDs/права/fences проверяются строго; перефразирование допустимо.

Артефакты: exact app/SDK/backend/worker/model/corpus pins, seed manifest, sanitized correlated JSON trace и timings, expected/actual evidence refs, rubric по каждому case, Android receipts/screenshots/playback evidence, ошибки и остаточные gates. Аудио/transcripts/private evidence — только в согласованном private artifact store; в GitHub лишь обезличенные итоги/refs без credentials, bearer, signed URLs, scans, private corpus или runtime secrets. PASS возможен только по новому trace соответствующего слоя; этот документ не содержит ни одного выполненного E2E.
