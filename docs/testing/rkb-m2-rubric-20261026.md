## Единица и проверка доказательств

- **Единица оценки — семейство вопроса**, а не число passages. В gold каждое обязательное утверждение/оговорка оформлены отдельным атомом. Для каждого атома есть **accepted-доказательство**: `document/source_id`, физическая страница/печатная страница и `passage_id` (URN); набор из нескольких источников допустим, если атом требует их сопоставления.
- Оценщик отдельно фиксирует: **что найдено поиском → что реально прочитано → что утверждено в ответе → что подтверждено приведёнными ссылками**. Присутствие фрагмента в search само по себе не значит, что модель его прочитала или доказала атом.
- Каждый атом засчитывается только если содержание, объект/период, отрицания и модальность источника верны, а прочитанное доказательство и ссылка подтверждают их. Для сопоставления книг нужны обе стороны и корректная атрибуция; различие этапов или степени уверенности **не превращается автоматически в противоречие**. Для неоднозначного вопроса обоснованное уточнение с конкретными кандидатами может быть полным результатом, произвольный выбор — нет.
- **Эквивалентное доказательство вне gold** не считается ни промахом, ни успехом автоматически: исход `unknown` до ручной проверки **по тем же атомам**. Если доказательство принято, зафиксировать новую версию accepted-набора и при необходимости переоценить все сравниваемые ответы одинаково.

## Исходы семейства

| Исход | Строгий критерий |
|---|---|
| **Полный обоснованный** | Все обязательные атомы подтверждены прочитанным evidence; нужные источники указаны; нет ложных утверждений, подмены объекта или утраты отрицания. |
| **Частичный (честный)** | Подтверждена лишь часть атомов или корректно обозначена недоказанная часть; **при доступном опровержении ложной предпосылки ответ «не найдено» тоже частичный**, не полный. |
| **Нет ответа** | Нет ни одного содержательно подтверждённого обязательного атома при технически успешном чтении, либо необоснованный отказ; отсутствие в выдаче само по себе не доказывает отрицание. |
| **Ложное утверждение** | Отдельный регистрируемый дефект ответа (может сопровождать иной исход), если вывод противоречит прочитанным источникам или утверждён без подтверждения. |
| **Технический сбой** | Ошибка/timeout/недоступность инструментов, не позволившие выполнить запланированное чтение; **отдельный исход**, не маскировать под «не найдено». |
| **Unknown (до проверки)** | Найдено возможное эквивалентное доказательство вне accepted-gold; ручная сверка по атомам ещё не проведена. В итоговый числитель успехов/провалов до разрешения не включать. |

**Ложная предпосылка:** явно найденное и предъявленное опровержение с достаточными ссылками = **полный**; «ничего не найдено» при реально имеющемся опровержении = **честный неполный**, не полный и не технический; технический сбой = отдельный исход. Не требовать искусственного позитивного ответа на отрицательный вопрос.

Публиковать по всем десяти и по каждой страте: числа **полный / частичный / нет / технический сбой / unknown**, отдельно число **ложных утверждений**; покрытие атомов, корректность ссылок на реально прочитанные доказательства, среднее число RKB-вызовов и медианы времени по одинаковому протоколу. Для сравнения P1/базиса — одни и те же модель, backend, K, payload и рубрика; фиксировать `n` и нерешённые `unknown`, не заменяя ими пропущенные исходы. Малые страты (`n=2`) — диагностические примеры, не основание для уверенных процентных выводов. Нельзя настраивать K или инструкцию на этих десяти семействах и затем называть их held-out.

**Граница:** документ — только правила, версии и агрегаты; без книг, текста passages, gold-атомов, новых механизмов, таблиц и кода.
