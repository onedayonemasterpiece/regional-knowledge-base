Для случаев с идентифицированным настоящим printed page сохранять оба соседних page refs, реальный span/region и source edition. Поверх `passage_ref` могут быть `continuation_ref` и figure proof IDs только после actual import, без самостоятельного построения фиктивных UUID. Отдельная safety матрица не должна подмешиваться к статистике исторической точности.

## 4. Заморозка, separation и двухступенчатая adjudication

**Preflight corpus** — только когда Шкипер **завершит** все выбранные imports (книги или несколько статей допустимы), подтвердит original intake/license/source edition hash, exact native accepted source revision, manifest страниц/region/passages, BGE vector/projection readiness, current ACL и withdrawal, available retrieval methods, restored/served runtime SHA. Исходные public files здесь — **proposed** fixture candidates, они *не импортированы этим ПМИ*. До source mapping запрещён оцениваемый retrieval. Нужен ≥3 независимых реальных произведения/статьи, минимум один RU и один DE, ≥30 реально eligible независимых held-out families, representative+challenge, native RU/DE и обоснованные cross-language; невозможно — честный `BATCH_BLOCKED_SOURCE`, не выдуманный PASS.

**Freeze manifest до первого run:** exact repo/installed code SHA, SQL schema+functions versions, dataset/PG active cursor, source IDs+SHA+edition+rights/licence+ACL/filter, page/region/accepted passage mapping, tokenizer/BGE-M3 checkpoint/dim/quantization, embeddings/index/projection versions, candidate budgets, neighbor flags, query/prompts, concurrent load, cache/warm, model/client version, grading rubric, family definitions and `gold_manifest_sha256`. Издать immutable `batch_id`, signer/reviewer и freeze timestamp. **Два рецензента** независимо проверяют gold по оригиналу (для Wichert при визуальной сомнительности — scan); при расхождении — явно `disputed` + третье решение **до открытия held-out результатов**. Нельзя «исправить истину», увидев неудачу модели; post-freeze изменение — новая `gold_version` и полный новый batch.

**Blinded execution:** другому ChatGPT окну на каждый bounded набор дать **только** `case_id`, RU/DE **вопросы**, разрешённый corpus/source scope, tools, frozen parameters/budget; **не давать** `minimal_answer`, anchors, rationale, категории с подсказкой, сопоставление с ответами других окон и gold-файл. Осторожно с доступом инструмента GitHub: запрет чтения `docs/testing/rkb-extraction-quality-cases-20261023.jsonl` явный, иначе blind недействителен; можно передать materialized question-only packet в самом поручении. Исполнитель возвращает точные имеющиеся tool calls, IDs/ranks/timings/errors, оригинальные source refs, final answer, abstention, latency с реальным model call, но **не заполняет оценку сам**. Traces с приватными текстами держать под исходными ACL; в PR только safe refs/hashes.

**Append-only:** результаты **каждой** попытки идут новой строкой отдельного run JSONL, структурой result-schema; статус `completed/timeout/denied/error/pending/unknown` с классом ошибки и границей, unknown effect не превращать в MISS. Нельзя удалять неудачи, задним числом перезаписывать `case_id`, gold, исходный run либо «сбрасывать таймер». Повтор после неизвестного эффекта — только штатный readback по тому же operation ID/trace, не новый независимый call. Результаты соседних окон должны быть слепыми друг к другу.

**Одна аналитическая точка:** до конца *всех* источников, arms, заблокированных/errored попыток и predeclared repeats **нет** структурных правок, SQL, re-chunking/re-import, модификации model prompt/weights по одиночной неудаче; фиксировать лишь факт и источник. Batch COMPLETE тогда и только тогда, когда `eligible family × query-variant × method × neighbor arm × repeat` имеет append-only исход (completed или explicit failure) и rubric review; временно pending/unknown → batch не завершён либо явный terminal unresolved с невыполненным quality gate. При изменении состава corpus — новый batch, даже если некоторые кейсы совпадают.

**После COMPLETE:** два независимых оценщика blind-score по источникам, gold unseal **после** сохранения raw outputs, adjudication disagreements и per-family failure taxonomy. Один пакетный root cause report (source absent/transcription/page-boundary/translation/encoder ANN/filter/rerank/fusion/neighbor noise/model hallucination/ACL/timing). Продукт принимает *одно* решение об улучшении, Opus отдельно назначает source/storage change и review, Шкипер отдельно организует **разрешённый** контролируемый reimport. Старые runs/gold/source pins неизменны; новые versions + **полный тот же held-out multi-source** прогон, paired Δ и roll-forward/rollback status; иначе нет causal выводов.

## 5. Arms, бюджеты, парность и производительность — ВСЕ NOT RUN

Взять точно методы [PR351](../audits/rkb-crosslanguage-search-decision-20261023.md): configured baseline, BGE-only, lexical-only, configured fusion, условные клиентский RU+DE запрос, historical aliases, BGE sparse, ColBERT rerank, cross-encoder и derived import-time translation, **только реально существующие/разрешённые runtime arms**. Не записывать отсутствующую ветку как 0 ms/PASS. Компонент rerank оценивать лишь при наличии source-relevant кандидата в first-stage set (candidate recall@100). Сравнивать ANN vs exact vector на том же source scope, не маскировать dense провалы lexical-предфильтром.

В рамках **того же** frozen held-out для каждого applicable retrieval arm три orthogonal соседних режима из **чужого** addendum PR351: **(N0)** нет соседей; **(N1)** только сильное continuation по **existing** legacy `continuation_context.py` (если native контракт действительно совместим, иначе `NOT IMPLEMENTED`); **(N2)** всегда ±1. Не строить новые контракты/регистры. Зафиксировать исходный ranked evidence + добавленные refs; один source/revision/ACL/withdrawal check на **каждого** соседа, no duplicate, wrong neighbor/noise и смысловую полноту на verified page-boundary. Это *план* — ни одного вызова нет.

**Pre-registration budgets:** minimum frozen 30 independent families, planned larger registry 59; rank `K=5/10`, candidate@100 (или фактически max≤100, иначе unavailable), одна и та же длина/язык/парафраз source scope, topK, candidate cap, tokenizer, chunk set, prompt/model, parameter settings across paired arms; для rerank K=10/20/50 только заранее выбранные comparators. Randomized/alternating AB order; warm/cold, cache hit/miss, no-parallel/4 user и concurrent import записывать отдельными стратификациями, не смешивать. Для preliminary устойчивого p95 план ≥200 *завершённых или явно завершившихся ошибкой* user attempts **на вариант** плюс независимая вторая серия (это **не** 200 successes). Если столько не проведено, показывать p95 как описательную оценку с N и CI, gate `NOT ESTABLISHED`. Не переписывать benchmark weights по held-out.

**Quality (по family, не по дубликатам query):** evidence Hit@5/Hit@10/MRR@10, candidate recall@100, original page/revision/source/provenance accuracy, statement precision+recall, answer coverage/completeness, no-answer abstention false-evidence rate, unsupported/hallucinated claims/contradiction, facts_only vs actual coherent Story.body (with no quota), noise neighbors / meaning-on-boundary. Для critical RU→DE slice замерять Hit@10 отдельно. Полные protected gates неизменны: dense-only Hit@5≥85%, Hit@10≥90%; critical RU→DE Hit@10≥85%. Sources absent/ineligible не равны успешным запросам и делают batch blocking, а true no-evidence in frozen eligible corpus — реальные negative cases с явно корректным abstention.

**Time end-to-end and per stage:** отдельные wall clocks `T_user→first usable evidence`, `T_user→first useful grounded answer`, `T_user→full answer`, `T_public_MCP`, `T_backend_ranked`; первый звук «проверяю» не useful answer. Включить клиентское формирование RU→DE варианта, queue/admission, WSS/Dev, SQL pool, tokenizer/encode, dense/ANN/lexical/fusion/hydration/ACL, соседей, передачу текста и **generation/validation моделью**. Выводить p50/p95 абсолютные + paired per-request delta of percentiles (не sum stage p95), bootstrap CI, duration/status каждого original request. Protected **backend warm p95≤1000 ms**, public **MCP p95≤1500 ms**, hard interaction evidence deadline **2000 ms** относятся к РАЗНЫМ clock границам; **не** подменять user→answer backend-only временем и не выдавать `T_user`≤1000 как уже измеренный gate.

**Cost/resource:** число bytes/Unicode chars/BGE tokens из original+adjacent passages в model context, query/response tokens, tool calls, ref count, wrong neighbor tokens, retrieval/tokenize/encode/model costs при доступных native traces. GPU/CPU time, GPU VRAM, RAM peaks, I/O bytes/read writes, sql plan/buffers on 100k scale если существующий telemetry путь их фактически предоставляет. `resource_unavailable` = `null + reason`, **никогда 0**. Состояния timeout/cancel/denied/degraded/pending в общем `N_attempts`; latency percentiles по завершённым с показанной censored/failure rate и timeout budget, а не по «самым быстрым» successes. Стоимость импорта/перевода/re-chunking/indexing/PG growth — **отдельная** one-time cost per physical page/per accepted semantic chunk с пиками I/O, не добавлять её тайно в per-query p95 и не исключать из решения storage.

## 6. Отбор, отказ и пределы достоверности

1. **Утверждения в фикшн и вторичной энциклопедии** — gold *внутри соответствующего документа*, а не верифицированный архивный факт. Текущий `source_verified_pending_second_adjudicator` **не** равен подписанному frozen gold.
2. **Статические статьи** допустимы вместо полных книг, но только после owner-approved import их фиксированных редакций и map к accepted source revision. В настоящем PR imports нет.
3. **Права** Википедии CC BY-SA и Wikisource/public domain/édition зафиксированы; media имеет собственные авторские права, нельзя считать весь вложенный файл свободным только по статье. Внешний публичный Gause 1994 не автоматически разрешён для републикации.
4. **Синтетика** проверяет refusal/scope/revision/prompt injection без реальных identity/grants/secret; ни одна synthetic запись не увеличивает `held-out` и не приравнивается к реальной «Истории».
5. Пока `accepted_passage_ref`, `source_page_id`, stage/saved и installed-runtime не получены от уполномоченного оператора, claims о source provenance ограничены публичной page/section, no pixels, no import quality proof.
6. Итог **NOT RUN** по всем retrieval/extraction/latency/CPU/GPU/resource/cost. Green docs validation не является импорта или production acceptance доказательством.
