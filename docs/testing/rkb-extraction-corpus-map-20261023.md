**Статус: PREPARED / NOT RUN / NO IMPORT.** Это документация источников, а не frozen batch, результаты поиска или разрешение на runtime. Нормативы: [реестр и методика](rkb-extraction-quality-registry-20261023.md), [76 JSONL cases](rkb-extraction-quality-cases-20261023.jsonl), [компактная schema будущих результатов](rkb-extraction-quality-result-schema-20261023.json), [merged PR351 / neighbors](../audits/rkb-crosslanguage-search-decision-20261023.md) и [protected acceptance §14](rkb-scalable-kaggle-acceptance-20261019.md), **который не изменён**.

## 3. Минимальный корпус будущего ПМИ — не gate для импорта или релиза

**CORE-3-ARTICLES:** (1) RU «Тевтонский орден» oldid **154951202** → (2) DE *Hochmeister* oldid **270545055** → (3) DE *Deutschmeister* oldid **250168686**. Три **отдельных** source identities и точных revisions, не одна комбинированная книга/сборник. После подтверждённого владельцем импорта всех трёх и native mapping предполагаются **38 held-out families**: RU 25 + DE 8 + DE 5 = **25 representative + 13 challenge**. Primary RU→DE = 5, primary DE→RU = 5; естественные RU→DE probes — у **13 DE families**, DE→RU probes — у **25 RU families**, но варианты одной family не создают новые независимые факты. Это тематически связанные статьи, а не репрезентативный весь RKB корпус. **Все 38 сейчас NOT ELIGIBLE для измерения**, пока нет native receipts/записей.

**CORE+WICHERT:** после отдельного корректного оформления серийной публикации *Die Gartenlaube* H.32–35 и page→edition map добавить 21 held-out Wichert, итого **59** (37 representative + 22 challenge) для narrative, fiction/historical distinction и printed page continuity. Никакой fake conversion *Die Gartenlaube* в книгу без источниковой атрибуции. Применимость long-book/PR351 Wichert-specific экспериментов остаётся отдельным readiness решением: CORE-3 статей не заменяет полную DE книгу или соответствующее издание.

**PDF-статья использует обычный постраничный импорт, не отдельный importer.** [Текущий `kaggle_importer.py::_start`](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/4a37fc6d48de4fc44ff504f9539a7fcf25652bfb/src/regional_knowledge/kaggle_importer.py#L255-L267) принимает attached PDF/DjVu, но отклоняет `metadata.catalog.kind != 'book'` с `target_source_components_unavailable`. Это **искусственный guard библиографических метаданных**, а не отсутствие общего page/stage pipeline: PDF, содержащий статью или журнальный материал, обрабатывается тем же `book_ingest(start) → book_pages → model-reviewed stage → status/finalize`, что и PDF-книга. Текущий guard остаётся действующим: **не подставлять ложное `kind=book`**; если для достоверного `article`/`journal_issue` metadata нужна его узкая source-коррекция, это **не новый импортёр**, не часть данного ПМИ и не условие обычного импорта книг/релиза.

**Не путать текущий каталог с импортом.** [`kaggle_source_read.py`](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/4a37fc6d48de4fc44ff504f9539a7fcf25652bfb/src/regional_knowledge/kaggle_source_read.py#L19-L25) сейчас реализует bounded `SOURCE_READ/source_catalog` find, а [`server.py target allowlist`](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/4a37fc6d48de4fc44ff504f9539a7fcf25652bfb/src/regional_knowledge/server.py#L296-L316) — каталоговый `book_find`. Отсутствие отдельного `article/journal get/cover/write` **не является gate** подготовки этого реестра, обычного постраничного текстового импорта или релиза. Никакого нового `article path`/catalog manager для ПМИ не требуется.

**Входной формат — отдельный вопрос от типа публикации.** Четыре предложенных immutable веб-оригинала заданы URL/`oldid`, а текущий attached intake принимает **PDF/DjVu, не HTML URL**. Для *будущего импорта именно этих веб-редакций* Шкипер сначала определяет допустимое **поддерживаемое представление входа** с подтверждённой связью oldid → фактические bytes/SHA-256, структура текста/таблиц/сносок/страниц и лицензия. PDF-статья, уже имеющая допустимый оригинал и корректные метаданные, не нуждается в иной механике постраничного чтения. Здесь ничего не конвертируется, не внедряется и не импортируется; никакого обхода действующего format/metadata guard.

**NOT_IMPORTED, SOURCE_MAP_PENDING и BATCH_BLOCKED_SOURCE относятся только к будущему оцениваемому blind multi-source прогону.** Пока нет exact native source/page/passage mapping, соответствующие families не входят в denominator и **NOT_RUN**, а не дают ложный search MISS/PASS. Это **не блокирует** составление списка/методики ПМИ, продолжающийся штатный постраничный импорт книг и других разрешённых источников или релиз. Шкипер остаётся единственным владельцем фактического импорта и receipts, Opus — review/merge, Продукт — quality; `finalize` означает завершение чтения, не автоматически полный accepted/Saved/searchable корпус.

## 4. Eligibility / freeze gates и источник истины для карты

1. **Edition+rights:** у каждого CORE original независимо от backend проверены точные oldid, актуальные полученные bytes/`SHA-256`, title/language/type/rights, документированы rendering/embedded templates/footnote/table/caption и безошибочная связь original→native input. Без доступа к original — **ORIGINAL_NEEDED**, mismatch — **EDITION_MISMATCH**; не оценивать как search MISS.
2. **Native receipt join (без фантазий):** из уже существующих **фактических** Shkiper `start/stage/apply/status` и разрешённых source-read receipts получить exact `native_document_id`, `accepted_revision`, физические `page_id`, `region/span_ref` и `accepted_passage_ref`, привязать printed страницы/anchors к accepted content. Только после доказанного join заполнять из null, иначе **SOURCE_MAP_PENDING / INELIGIBLE_SOURCE_NOT_IMPORTED**; внешний URL либо Story UUID не заменяет source evidence.
3. **Visibility+index:** подтвердить current applied frontier **отдельно** от verified Dataset Saved, source ACL/visibility/withdrawn state, BGE vector/lexical projection, точный SQL/code/model/tokenizer/index/source scope. Пустой доступ, stale revision или отсутствующий indexed accepted passage — block/ineligible, не retrieval MISS. `book_find`/`fetch` годятся только для последующего authorized retrieval, не как полный original→storage completeness oracle.
4. **Independent gold+freeze:** два рецензента вычитывают immutable originals **вне system fetch**, заранее размечают отсутствующие в extracted text факты, отрицания, narrative/facts_only, page/span, disputes; adjudication до раскрытия ответов. Заморозить ≥3 реально imported work/article sources, RU+DE, ≥30 независимых *eligible* held-out families (CORE предлагает 38, но не гарантирует eligibility), representative/challenge, точную матрицу source/edition→case, original SHA, accepted revision, ACL, installed code/SQL/model, search arms/neighbor flags/repeats, gold manifest SHA. При недоборе — **BATCH_BLOCKED_SOURCE**, не PASS.
5. **Только отдельный будущий blind run:** question-only packet без answers/anchors и доступа к JSONL gold. Только методы, реально поддержанные runtime; остальные **NOT IMPLEMENTED**, не 0ms. Применить PR351 N0/N1/N2, paired Hit@K, client-inclusive p50/p95, failures и source/ACL-правила исключительно по существующей методике; никаких новых harness. Сначала все frozen sources×arms×variants×repeats в terminal receipt → **EXECUTION_COMPLETE**; затем независимая оценка, полный raw freeze → **ADJUDICATION_COMPLETE**, и только затем единый multi-source вывод о доработках.

**На дату среза:** web sources proposed=4, web sources confirmed native imported=0, mapped eligible web held-out=0, independent Gause original oracle=missing, execution=NOT_RUN (76/76). **Opus** — sole review/merge; **Продукт** — quality; **Шкипер** — sole future runtime/import.
