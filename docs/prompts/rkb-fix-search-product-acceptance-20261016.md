## Цель и границы

Продолжи работу над onedayonemasterpiece/regional-knowledge-base до продуктового результата: существующие книги и истории находятся по смысловым вопросам, ответы подтверждаются собственными источниками, результаты повторной проверки записаны в журнал.

Это задача на исправление конкретных проблем, не новый общий аудит, повторная уборка или новая платформа. Выбирай простое универсальное решение, без подгонки под книги, имена, вопросы или ID. Следующую книгу/статью владелец принесёт отдельно. Сейчас новый импорт не запускай и старые незавершённые импорты автоматически не продолжай.

## 1. Исправить смысловой поиск историй

Подтверждённый пример: story_search с mode=semantic и вопросом «Как строили большой храм на заболоченном острове?» возвращает lexical_degraded, indexing_state=local_fts_ready_vector_awaiting_worker. История «Зачем для Кафедрального собора потребовались тысячи дубовых свай» отсутствует среди первых пяти результатов. По лексическому запросу «собор» находится первой.

Проверь актуальный контракт индекса историй, предусмотренный worker, очередь и маршрутизацию. Исправь причину, не только статус. Не выдавай lexical fallback за semantic PASS. Не добавляй новый механизм, если достаточно довести существующий. Если выяснится, что необходимая часть отсутствует, реализуй минимальное связное решение в рамках согласованных требований, а не замаскируй отсутствие функции.

## 2. Исправить пропуск книжного свидетельства

Подтверждённый вопрос: «Кто начал возводить собор на восточной части острова Кнайпхоф и каким замышлялось здание?»

Ожидаемый фрагмент Гаузе существует: отдельный fetch подтвердил активную revision 4, physical_page_index=8. В восьми результатах вопроса его не было, первые три проверенных кандидата не отвечали на вопрос. Это не отсутствие материала в корпусе.

Найди источник штатно через catalog; проверь исходный фрагмент, актуальную revision, query encoding, векторный маршрут, фильтры и ранжирование. Зафиксируй gold до исправления. Не заменяй естественный вопрос ключевыми словами ради зелёного результата.

Предыдущая малая выборка: шесть семейств фактов двух книг, 12 положительных попыток, 11 ответов, Hit@5=10/11 среди ответов и покрытие программы 10/12. RU→DE=3/3 rank1. Это диагностика, не общий holdout. Возвращалось восемь результатов, полноценный Hit@10 не измерен.

## 3. Дочитать собственные свидетельства историй

У истории о сваях подтверждены свежесть источника и точное совпадение короткого excerpt, но он сам по себе не доказывает всю proposition. Прочитай полный релевантный контекст и проверь существенные утверждения.

Для истории «Почему арбитраж епископа 1246 года изменил план будущего Кёнигсберга» первое утверждение частично проверено по Гаузе; собственное свидетельство Бруннека осталось непрочитанным.

sources_page реально показывает обе книги, хотя compact snapshot.source_refs показывает одну. Не объявляй это потерей источника без проверки авторитетного представления. Candidates без editorial variants ожидаемо не готовы к публикации: это не само по себе дефект извлечения.

## 4. Локализовать задержку

На 11 успешных положительных запросах backend p50=408,3 мс, p95/max=1871,4 мс; наблюдаемое полное MCP-время p50=3571 мс, p95/max=8364 мс. Перцентили nearest-rank, выборка мала; cold/warm не разделены, одновременно шли другие read-only проверки.

Повтори ограниченную серию с явной границей измерения, cold/warm и условиями concurrency. Отдели backend от транспортной обвязки. Не объявляй всю wall-задержку дефектом backend и не строй новый транспорт без доказательства. Исправь подтверждённые лишние расходы; укажи, что осталось вне контроля.

## Четыре отменённых вызова и ограничения безопасности

Во всех четырёх случаях инструмент вернул точный текст:

`user cancelled MCP tool call`

Это НЕ доказанный отказ системы безопасности и НЕ доказанный сбой backend. Причина отмены не установлена. Нет достаточных данных, чтобы утверждать, кто её инициировал и дошёл ли каждый вызов до сервера. Не следует переименовывать эти четыре случая в «четыре отказа безопасности».

| Вызов | Что осталось непроверенным |
| --- | --- |
| search, query «Иоганнес Кларе строительство собора после 1330», scope книги Гаузе | Один положительный поисковый кейс; wall отменённой попытки 1992 мс. |
| fetch для третьего заранее выбранного gold-фрагмента Бруннека, B3 | Отдельное подтверждение полного ответа fetch; фрагмент ранее прочитан через corpus_read. Wall 1980 мс. |
| story_get, view=evidence_page, межкнижная история об арбитраже епископа 1246 года | Полные собственные свидетельства сквозной истории. |
| corpus_read книги Гаузе, source_revision=4, cursor="20" | Продолжение чтения контекста источника. |

Приватные document/story/chunk ID и исходные цитаты не публикуются. Получи актуальные ID через каталог и поиск названий. Старый cursor используй лишь при подтверждённой той же revision и правилах текущего API.

Локальный файл прежнего исполнителя с B3 не считается автоматически доступным новому окну. Если точный старый B3 нельзя восстановить, отметь его как невоспроизведённый и создай новый независимый тест; не выдавай замену за старый retest.

Отменённые вызовы не повторяли циклом. Продолжать незавершённые проверки можно только по фактическому разрешению владельца и текущим правилам. При новом отказе/отмене зафиксируй действие, цель и точную ошибку. Не обходи запрет другой учётной записью, инструментом, транспортом или исполнителем. Не изменяй безопасность и авторизацию ради теста.

Отдельно, НЕ в эти четыре случая, при проверке уборки file_stat для .venv второй рабочей копии вернул symlink_escape: «symlinks are not readable by probes». Обхода не было; такая проверка для исправления поиска не требуется.

## Способ работы и полномочия

Для фактов и продуктовых проверок используй штатные прямые MCP-инструменты. OpenCode не запускай по умолчанию ради простого чтения состояния. Для кода следуй правилам доступной среды, AGENTS.md и репозитория.

Не останавливайся на ещё одном отчёте «проблема воспроизведена»: внеси минимальное универсальное исправление, выполни регрессии и повтори пользовательский сценарий. При блокировке продолжай независимую разрешённую работу.

Этот документ не создаёт полномочий сверх поручения владельца. Используй его реальные разрешения на изменения, коммиты и PR; не переспрашивай уже разрешённое. Production deploy только при соответствующем явном разрешении. Если его нет, подготовь проверенный SHA, откат и один конкретный запрос. Не объявляй исправление доступным через MCP до проверки runtime. Другие проекты, секреты, ACL, исходные книги и незавершённые импорты не трогай.

## Повторная приёмка и готовый результат

1. Точные запросы, естественные перефразы и RU→DE по шести семействам двух книг, gold зафиксирован до поиска.
2. Несколько дополнительных независимых примеров, не использованных для настройки.
3. Естественное нахождение контрольных историй, фактический semantic mode без скрытого fallback.
4. Полный собственный источник каждого существенного утверждения двух контрольных историй.
5. Два отрицательных вопроса: нерелевантные кандидаты не превращаются в подтверждённый ответ. Наличие кандидатов само по себе не является галлюцинацией search.
6. Backend и MCP latency, все ошибки/отмены, без удаления неудобных попыток из отчёта.
7. Применимые регрессионные проверки окончательного кода.

Обнови журнал, сохраняя прежние записи: defect → причина → изменение → retest. Приватные excerpts/IDs/raw traces не публикуй в открытом GitHub.

Финальный ответ: что исправлено, какой SHA реально обслуживает проверенный MCP, что PASS/FAIL/INCONCLUSIVE/NOT RUN и можно ли брать следующий одиночный источник. Дай ссылки на изменения и результат.

Не делай полный массовый holdout или нагрузочный стенд препятствием для следующего контролируемого импорта. Но зелёные unit-тесты, PR и готовый индекс не подменяют работающий пользовательский поиск.
