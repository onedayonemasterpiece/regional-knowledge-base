## Проблема (факты)

- Чек-лист MCP п.3 требует записывать людей, места, организации и события, которые называет страница, с evidence.
  Это требование продукта, а не обвязка.
- Телеметрия API за 30.10 10:00–14:48: на 387 принятых страницах трёх книг (Boetticher 3c17b8ed, Brünneck bccc8a65,
  «Восточная Пруссия» 8edf556f) `entity_candidate_count = 0`. `entity_list` по Boetticher и Brünneck пуст.
  Последние сущности были 27.10 (115 штук, Albinus).
- Причина в контракте. `GraphEvidence` (`src/regional_knowledge/entity_graph.py:45`) требует UUID `chunk_id/page_id/region_id`,
  а `validate_staged_bundle` (`entity_graph.py:132–151`) ищет `chunk_id` среди уже скомпилированных фрагментов.
  Внутри одного stage-пакета модель знает только свои `chunk_key/region_key`; UUID появляется после приёмки.
  Значит, требование «в том же проходе» модель выполнить не может и пропускает сущности.
- Истории уже решают ту же задачу: `StageStoryEvidenceInput` принимает `chunk_key` + `region_key` того же пакета.
- Ошибка маскируется. `kaggle_importer.py:940–942` превращает любой `ValueError/KeyError/TypeError` в
  `invalid_small_source_input` без указания поля, и в журнале API причины нет.
  Brünneck с 14:42 стоит на физ.152–154 именно с этой ошибкой; окно не может само понять, что исправить.
