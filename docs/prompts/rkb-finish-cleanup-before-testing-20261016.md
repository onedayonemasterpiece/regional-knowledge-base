## Разрешение владельца и практическая безопасность

Владелец поручил закончить порядок и отдельно подтвердил: «это вопрос про старые каталоги базы знаний региона? да разрешаю проверить и подчистить. по остальным проектам сейчас окно чатгпт по разбору работает». Затем уточнил: «.md уже сразу на наведение порядка ставь».

Это разрешение на уборку RKB, не на удаление неизвестных данных. Не спрашивай заново о каждом обратимом техническом шаге в согласованной области. Сохраняй отдельные обязательные подтверждения инструмента/политики, если действие необратимо или расширяет область.

До удаления конкретного каталога установи одновременно: его содержимое учтено; уникальное сохранено и проверено; импорт/сервис/активная задача его не использует; Git/среда восстановимы; операция штатная. Если это не доказано, сохраняй каталог, объясни точную причину и продолжай остальное. Не использовать blanket `clean -fdx`, `reset --hard`, force removal или возраст папки как доказательство ненужности.

Не читай и не публикуй секреты, env, credentials или приватное содержимое книг. Не коммить raw artifacts и секретные конфигурации. Сопоставление процессов с путями должно возвращать только необходимые PID/path/role, без сырых командных строк с токенами.

## Почему предыдущая проверка не закончила уборку

Детерминированные Git/file checks выполнены через DevCoveer. Проблемой оставалась не инвентаризация Git, а фактическое использование двух каталогов процессами.

- У project RKB host inventory не предоставил registered services/roots/runtimes.
- `host_probe process_tree` требует registered service; без него вернул schema invalid_input. Это ограничение этого typed-пути, не запрет серверного доступа вообще.
- Проверенный старый process script показывает comm/CPU/RSS, но не cwd/exe/maps и не доказывает незанятость каталогов.
- Исследованный `run_tool` принимает project-relative script/module, но не inline Python/-c. Не считать это вечным ограничением: проверь live `direct_ops_v2 describe` и доступные методы в новом окне.
- `/home/dev/AGENTS.md` запрещает новые временные probe scripts в repo/artifacts и /tmp. Для временных артефактов предусмотрен managed `/home/dev/artifacts/<project>/<task>` с `.artifact.json` через dev-artifacts. Соблюдай актуальный контракт; не обходи его.
- Если штатный доступ нового окна позволяет узкое чтение /proc cwd/exe/maps и необходимых служебных path references, используй его напрямую. Permission-denied означает неизвестное покрытие, не «процессов нет».
- Не ограничивайся повторением неудачного `process_tree`: выясни доступный законный путь и заверши проверку. Но не объявляй её выполненной по одной пустой выдаче.

По разрешению владельца запустили один read-only OpenCode `dvt_f64e0c3f78084399a86af4cff77eb03b`. Он оставался busy без tool calls/результата. Перед передачей этой задачи остановлен: итог interrupted, session idle, MessageAbortedError. Использование каталогов им **не проверено**. Не возобновлять этот зависший запуск автоматически и не создавать ещё один такой запуск вместо прямой работы.
