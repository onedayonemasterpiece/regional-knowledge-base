# Задание RKB-Импорт R1: предел 512 токенов проверять при приёме страницы, а не после применения

Заказчик: RKB-Импорт (Claude). Владелец 29.10: импорт должен быть надёжным — нестандартность не должна молча ломать или останавливать импорт.

## Наблюдение (живое, Albinus 28–29.10)

p59 и p60 Albinus: `book_ingest(stage)` ответил «принято», через ~30 с фаза text в Kaggle отказала `complete_native_input_exceeds_512_tokens` (один фрагмент длиннее 512 токенов). Читатель узнал это только из следующего status, без указания фрагмента. p60 стояла ~11 ч. p59 вообще прошла незамеченной: читатель ушёл дальше, дыра найдена вручную через сутки.

## Код (main)

- В Kaggle предел проверяется после применения: `kaggle_source_materializer.py:315` (`complete_native_input_exceeds_512_tokens`).
- На Dev уже есть точный счётчик BGE-токенов и проверка для старого пути: `kaggle_importer.py:~560-568` (`token_counts = await self._counts(...)`, `complete_source_input_exceeds_512_tokens`). Native stage (`kaggle_native_source_intake.py`, `stage`) им не пользуется.

## Что сделать

В native `stage` до приёма пакета посчитать токены **того же самого полного входа**, который потом кодирует Kaggle (текст фрагмента вместе с префиксом и подписями — как в `kaggle_source_materializer.py:~300-315`), тем же существующим счётчиком `_counts`. Если какой-то фрагмент > 512 — отказ `invalid_query` с кодом `complete_source_input_exceeds_512_tokens` и `chunk_key` этого фрагмента. Пакет не принимается, читатель исправляет и повторяет тот же stage.

Если собрать на Dev ровно тот же вход, что в Kaggle, нельзя без дублирования логики — переиспользовать общую функцию сборки, а не копировать. Если это невозможно — BLOCKED с объяснением, без приблизительного подсчёта.

## Чего нельзя

- Не менять предел 512, токенизатор, правила нарезки и инструкции о размере фрагментов (стандарт — RKB-Ответы).
- Новые состояния, флаги, ретраи, сервисы — нет.

## Один различающий тест

Пакет с одним фрагментом, чей полный вход > 512 токенов: на текущем main stage принимается, с правкой — отказ с `chunk_key` до приёма, ничего не записано. Пакет с фрагментами ≤ 512 принимается как раньше.
