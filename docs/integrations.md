# Cross-project integration contracts

Updated 2026-10-20. The [single handoff](prompts/rkb-scalable-kaggle-implementation-20261019.md) is the target; prior release reports are scoped historical evidence. Reuse stable references and narrow owner APIs, without copying product databases or adding a new integration service. An interface or a healthy PH process does not establish a working PH→RKB provider or measured voice latency.

| Product | Owns | RKB relationship |
|---|---|---|

| Street Story | Physical POI identity, aliases, geometry/lifecycle decisions and its own POI arbitration. | Source evidence events, model-selected POI links, poi_context; RKB independent case may link POI but is not owned by POI arbitration. |

## Clients and request completion

Kaliningrad Base is the single RKB Slack bot. **Dot→tools and Mira→tools are two independent smart routes**; preserve both. Personal MCP and Mira need no mandatory Slack or Dot reasoning intermediary. All routes share one verified person model, equal-person admission and canonical domain authority. Durable questions/effects also share per-dialog order, history and receipts. Accepted, domain Saved and delivered/native result-hash ACK are separate durable facts; UNKNOWN delivery reconciles before resend while unrelated work continues.

The physical read route is **PH typed provider→existing DevCoveer auth/admission→authenticated outbound notebook WSS**. The notebook initiates the socket; no public Kaggle listener, extra WSS relay, HTTP self-call or second dispatcher is introduced. Kaggle performs encode+SQL+bounded hydration in one typed RPC and returns a ready evidence/story pack; the query vector does not travel back through Dev. Reuse the existing ASGI/BgeQueue/controller authority. There is no verified reusable native gateway in this contract; a language change must replace a measured expensive component, not add another service/authority.

Read_query takes a bounded RAM permit and uses QUERY/QUERY_RESULT/CANCEL_QUERY, with request_id, generation/deadline and min_data_seq. It has no per-read fsync, remote intake/seal, durable status, RESUME or resultSaved promise. Durable_question/request and mutation/provider-effect retain exact remote intake, saved outcomes, ordering and receipt continuation after reconnect. A nested read inside a managed question does not create another question/queue. The existing control index checks unresolved mutations across Dot/Mira/MCP by canonical person and typed resource/scope dependencies at read start and delivery. An intersecting pending/UNKNOWN write returns prior_write_pending with observed freshness; shared-resource changes affect all relevant readers. An unrelated private-draft UNKNOWN does not block accepted-book search; unproven independence is treated as dependency. Per-dialog order is separate. See [handoff §§5.2, 10.2](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Expand PH's current search-only adapter with resource-bound transport/identity and **versioned v2** status/freshness/min-cursor/continuation, allowed research operations and mode-specific result/ACK. The strict v1 evidence/mode normalizer cannot represent all new states: adapt only fully representable success; otherwise use its existing unavailable/error boundary, never empty hybrid success. Keep the Live tool surface small (`knowledge_search`); progressive research capability belongs to the typed owning-product adapter, not an indiscriminate dump of admin tools into voice. Preserve default 3/max 5 evidence, query≤1000 characters and current text/metadata limits in [MCP](mcp.md); no silent truncation. No second voice app/session/IAM/queue. A spoken story reads the saved body or saved adaptation, not praise/summary invented during delivery. Evidence and bibliography appear on screen; proof follows its audience policy.

Every adapter checks scoped policy deltas against full item source/variant/grant dependencies, including cross-book prose and bibliography. Drop whole affected items and their display/continuation fields; mark output degraded/evidence_withdrawn even with zero items, never empty success. Unaffected reads continue, but incomplete/compacted policy evidence fails closed for the affected scope/result; a current cursor alone is insufficient. The access barrier becomes remote-durable before confirming new RKB access blocked, without waiting for Kaggle; PG withdrawal/public purge remain pending until commit/readback under [handoff §§6, 10.1](prompts/rkb-scalable-kaggle-implementation-20261019.md).

PH asynchronously checkpoints exact ordered evidence/context refs in its existing private tool/utterance store under `(session, turn_generation, tool_call_id)`, with committed-turn binding and disposition. An ephemeral answer does not wait for this write. A crash gap yields context_gap/evidence_context_unavailable, never a fresh search masquerading as the earlier answer's sources. Continuation/context refs grant no capability and are reauthorized on reuse. This recovery state follows [handoff §10.4](prompts/rkb-scalable-kaggle-implementation-20261019.md), separately from telemetry and durable RKB ACK.

Read telemetry uses a separate bounded buffer/batched sink, never the queue SQLite write lock or an awaited remote append. Bodies, credentials and private origins are not logs; a counted drop is allowed. PH utterance semantic state and checkpoints remain durable dialog recovery, including `_mark_semantic_observed`. Measure tool_lock_wait separately from tool execution; allow only bounded independent reads to overlap through existing admission. Do not remove effect/dialog locks wholesale. Late results are discarded after generation/deadline/revocation or withdrawal checks; canceling a read does not cancel/retry an accepted effect or another consumer's job.

The optional phrase “Мира, хорошо подумай” may become an explicit delegation to Dot only after a real comparative pilot shows benefit; it is **not part of the base implementation**. After a real PH provider exists, [acceptance](testing/rkb-scalable-kaggle-acceptance-20261019.md) compares Mira and Dot on the same queries, corpus/revisions and rights, with quality, completeness, source grounding, time to first useful answer and full-answer time. Do not assume either agent is better or present absent PH→RKB measurements as a performance baseline.

## Evidence and media contracts

Use stable opaque `knowledge://documents/...`, `knowledge://illustrations/...`, POI/layer refs and native provider entry refs. Identity is not authority. No permanent signed URLs or bearer tokens inside refs. Source activation and outbox event commit together; downstream map/provider downtime does not roll back a valid book. Exact source revision/payload/operation keys and native receipts make retry idempotent.

Source facts, people, dates, observations, GEO, stories and disagreement proposals share one bounded reading/research frontier. Reconcile semantic identity before linking entities/POIs; nearby coordinates/name similarity does not suffice. Preserve graph_fetch/related/stage, poi_registry search/get/select/create and poi_context without whole graph dumps. Accepted source-side places can remain unmapped.

Illustrations are public; stripe quote/page proof requires owner/demo/expert/local_historian capability and suitable delivery route. Full originals and private drafts are separate. A mirror's private storage location does not determine the public class of a returned illustration. Keep source, display, provider rendition and delivery SHA separately; exact originals require exact SHA, transformed media need their own native rendition readback. Do not require equality of different renditions or pHash as proof. Missing provider digest fails closed.

VibePublish remains uploader and provider limiter. Owner-provided `TELEGRAM_RKB1`/`TELEGRAM_RKB2` are the initial independent session pool for direct Kaggle reads, subject to stage-0 authorization/archive-access checks (the second was reported empty and must be rechecked). One exclusive session lease per run limits simultaneous runs together with owner-authorized Kaggle capacity; latency work cannot invent additional reader runs or cloned auth keys. No second uploader or unbounded PDF in model JSON. Topic2 originals/topic4 images are configuration verified during implementation, not credentials copied here. text_search_ready and archive_ready advance independently within the existing run; unavailable original/proof bytes remain explicit and do not delay eligible text search.

Same-host RKB↔Street Story/Vibe calls use dedicated target-scoped identity on loopback/Unix socket. Do not use owner browser OAuth, public detours or another proxy. Kaggle must reach the owner via authenticated approved transport; its localhost is not DevCoveer.

## Public discussion and tasks

Preserve VK editorial queue/scheduling/cancellation, registered-post comment ingestion/moderation and subscriptions through VibePublish. Actual provider allowlist/token permissions must be verified; generic read.thread is not VK comments support. RKB retains case question/arguments/conclusions and history; PH task_done does not resolve a research need automatically.

Astro static pages use public selected projection, permanent opaque slugs, no login/backend dependency, current and last-supported conclusion, exact published revision and last-known-good output. Real URL exists only after first successful readback. Late build/revocation is generation-fenced and purges/rebuilds HTML/JSON/OG/assets. Restricted proof/private drafts never enter the export.

Do not import old non-GEO content while preserving these functions. Reuse PR151 code only after current-diff review; branch-level tests are not production PASS. Verify at least one real non-owner across personal MCP/Slack/Mira, authoritative POI/map receipt, actual provider result/hash ACK and safe public page.
