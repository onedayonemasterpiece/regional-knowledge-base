# РКБ · «Читать первоисточник»: PDF главы/статьи и аудиоверсия

**Продуктовое предложение владельца · 26.10.2026. Статус: design / implementation pending.** Этот документ фиксирует приоритеты и проверяемый контракт, **не утверждает, что экспорт реализован, развернут или разрешён для всех книг**. P0 — PDF; P1 — асинхронное аудио. Не выполнять Kaggle launch/deploy, менять защищённые requirements или выдавать приватный корпус ради реализации этой спецификации.

## 1. Пользовательский сценарий и границы

1. Пользователь получает обычный поисковый ответ RKB с одной или несколькими цитатами, привязанными к принятому изданию, исходной странице и source/chunk/span.
2. Отмечает конкретные цитаты и выбирает **«Читать первоисточник»**. Система показывает: книгу/журнал, предполагаемую статью/главу, исходные страницы, объём, полноту принятых страниц и доступность PDF/аудио. Пользователь подтверждает выбранные законченные единицы; при неуверенности границы выбирает их явно.
3. **P0:** запрос запускает асинхронную подготовку PDF; пользователь получает operation/status и затем авторизованную ссылку/файл. PDF может собираться за секунды на прогретой инфраструктуре, но обещать время до измерений нельзя. Холодный Kaggle, очередь и неполный источник — отдельные статусы.
4. **P1:** отдельным выбором запускается озвучка **той же зафиксированной единицы и текста**; долгую работу можно продолжать после разрыва чата. У PDF и MP3 независимые статусы: PDF готов, MP3 в очереди — нормальный исход.
5. Несколько цитат **внутри одной единицы** дают один PDF этой единицы без повторов. Несколько единиц (в том числе из разных книг) дают один сборный PDF с индивидуальными разделами и полноценной библиографией для каждого; запрет хотя бы одной не должен незаметно терять материал. Перед запуском пользователь видит доступные/недоступные элементы и может выбрать разрешённые.

Не вводить перевод, литературную редактуру, современную орфографию, пересказ, генерацию недостающих абзацев, неявную «авторскую реконструкцию». «Статья» в сборнике/журнале и «глава» в монографии являются **логическими единицами**, а не произвольными 10 страницами. Количество страниц — измеряемый технический/тарифный фактор, не критерий смысловой границы.

## 2. Что уже есть в RKB; чего пока нет

- `src/regional_knowledge/kaggle_source_read.py`: `source_catalog` и `accepted_chunks` — **ограниченные поисковые проекции**. `accepted_chunks` ограничен диапазоном до четырёх физических страниц и выдаёт максимум восемь passage records с источниковыми refs; это **не** API выдачи готовой статьи. Убирать ограничения в search-read ради PDF нельзя.
- `docs/operations/source-backed-semantic-passages.md`, `docs/ingestion.md`: на стороне Kaggle/PG сохраняются проверенные source regions, heading/body/footnotes, source spans, страницы и происхождение. Их можно использовать для отдельной последовательной сборки, избегая дублирования, обрыва смысловых чанков и подмены автора.
- `docs/operations/article-search-scope.md`: article IDs и принадлежность к одному accepted parent revision уже предназначены для поиска. **Article search scope != подтверждённый полный исходный текст статьи для экспорта.** Содержание двух статей на одной странице нельзя выдавать как одну статью, выбрав только page range.
- `docs/rights.md`: открытая поисковая проекция, доказательные crop/stripe и полный оригинальный PDF/DjVu имеют **разные права**. Роль demo/expert/local_historian + `scan_proof_read` не разрешает автоматически выдать главу.
- В имеющемся `source_catalog` видны основные поля (title, authors, publication_year), но **не подтверждена структурированная полнота ISBN, УДК, ББК, ISSN/DOI и выходных данных**. Их нельзя придумывать из названия/года; нужен аудит доступных stage metadata и, при необходимости, их пополнение при импорте/коррекции.
- Пакеты книги могут активироваться **постранично до finalize** (контракт сервера `book_ingest`). Наличие поисковой цитаты не означает, что вся глава прочитана, принята или уже принадлежит установленной структурной единице.

**Главный пробел P0:** нет доказанного устойчивого отображения «цитата → вся завершённая единица → упорядоченный без потерь принятый авторский текст». Оно важнее выбора PDF-библиотеки.

## 3. Источник истины и определение единицы

Единица имеет stable identity: `source_id`, `accepted_revision`, `unit_id`, `unit_kind` (`article|chapter|section`), `unit_title`, `start_anchor`, `end_anchor`, ordered source span references, source page labels и `boundary_evidence`. Существующий article ID использовать как опору, если он привязан к этому exact revision; не создавать второй независимый реестр статей. Для глав пока требуется подтверждённая карта границ либо явное согласование диапазона с исходным заголовком и концом. Сохранять границы в существующем принятом source graph/его минимальном продолжении, **не** в новой книжной базе на Dev.

Граница допускается **внутри физической страницы и внутри source region**, а не только на целой странице: на одной странице могут закончиться статья A и начаться B. Отсылки в тексте ответа служат селекторами, но не задают автоматически точные границы главы. Порядок — accepted page index + accepted reading_order + соответствующие spans, а не порядок релевантности passage_search. Для таблиц, примечаний, списков, исторической орфографии, сносок на другие страницы использовать явную структурную модель.

P0 допускает только:
- уже полностью accepted и active unit с проверяемыми началом/концом и *полным покрытием* её исходных spans;
- проверенные author text + headings + footnotes/captions/tables, если имеющийся renderer корректно передаёт их; оригинальные изображения только при отдельном действующем праве на соответствующую rendition.

Если единица не завершена, есть нечитанные/непринятые страницы, неоднозначный reading order, отсутствующий/сломанный символ, нечитаемая формула, непроверенная граница или неподдерживаемая структура: `needs_source_review` / `needs_boundary_confirmation` / `unsupported_layout`, **не** «готовый» неполный PDF. Успешный retrieval и наличие native text сами по себе не являются доказательством точности; для image-only DjVu нельзя незаметно включать OCR/LLM, запрещённые текущим импортным контрактом.

Для нескольких ссылок в одну единицу дедупликация делается по `source_id + revision + unit_id`. Межкнижная компиляция состоит из отдельных авторизованных единиц: текст не перемешивается, перед каждой — свой титул и источник. Генерируемые служебные элементы PDF явно отделяются от буквального авторского текста.

## 4. P0 · выходной PDF и библиографическая честность

**Документ:** A4 (при желании позже — A5), переосмысленная удобочитаемая типографика **издания для чтения**, не фотокопия страниц; русские и немецкие тексты оставлять на языке оригинала. По умолчанию: основной кегль 11–12 pt, межстрочный интервал ≈1.3, поля ≈20–23 мм, абзацный отступ первой строки 4–6 мм, осмысленные `keep-with-next`/widow-orphan правила, главы с заголовками, корректные сноски и таблицы. Межабзацные интервалы не заменяют «красную строку». Все символы кириллицы/латиницы/исторической орфографии должны отображаться и копироваться; шрифты внедряются в PDF, лицензии шрифтов проверяются; PDF не должен быть растром. CSS/HTML paged print engine (например WeasyPrint) или иной renderer выбрать после fixture-spike по многостраничным сноскам, Unicode и скорости; никакой отдельной модели для вёрстки.

**Библиографический паспорт / первая страница:**
- исходные автор(ы), заголовок произведения, название книги/журнала/сборника и заголовок главы/статьи;
- составители, редакторы, переводчики, издатель/место/год/номер/том, исходные физические/печатные страницы — **в пределах подтверждённых данных конкретного издания**;
- ISBN для книги/издания; ISSN для серии/журнала; DOI статьи, УДК и ББК, если присутствуют и проверены; отсутствие поля не заменяется догадкой или чужим ISBN;
- источник экземпляра и устойчивые `source_id / edition_id / revision` либо внешний идентификатор для проверяемости, точные страницы по исходнику и дата формирования;
- подпись: **«Подготовлено сервисом „База знаний региона: Калининградская область“ на основе указанного первоисточника. Не является оригинальным издательским макетом»**;
- сведения о праве/лицензии и условии использования, когда это требуется подтверждённым источником.

**Тело:** точные авторские абзацы, заголовки, цитаты внутри текста, сохранённые сноски/примечания и специальные знаки, где supported. Никаких исправлений текста «для плавности»; косметические переносы/неразрывные пробелы на уровне верстки не должны менять копируемый текст. Новые номера страниц PDF не подменяют печатные номера книги. Исходные страницы указываются деликатно на полях/в колонтитуле или в оглавлении соответствий. При нескольких цитатах разрешается добавлять **внешние** гиперссылки/закладки на места цитирования, но не вставлять метки в авторский текст.

**Техническое:** PDF text-searchable, копируемый, встроенные шрифты, корректный `ToUnicode`, метаданные title/author/source/creator, bookmarks для составных документов, воспроизводимая сборка по pinned source & renderer version, проверенный MIME/byte size/readback. Accessibility/UA/PDF-A — желаемые следующие требования, не приписывать сертификат без тестов. Приватные идентификаторы/URL/учётные данные не помещать в PDF. При невозможности сохранить слова и примечания — ошибка, а не тихое пропускание.

## 5. Права доступа ≠ коммерческий уровень

Нужны **две независимые проверки**:

1. **User entitlement**: демо, профессионал, краевед, преподаватель (последние два — возможные продуктовые названия/статусы, **не автоматически существующие IAM роли**) определяют видимые действия, размер пакета, справедливую очередь/квоты. Использовать существующую каноническую identity/grant систему, не создавать новый IAM.
2. **Source-specific reproduction permission**: подтверждённое право на **полнотекстовый экспорт конкретной статьи/главы и аудиопереработку**. Текущая возможность поиска и `scan_proof_read`, собственность на скан, роль учителя, публичность иллюстрации или пометка `public_domain_candidate` **не достаточны**. Требуются подтверждённые сведения о правомерном объёме/территории/канале/сроке лицензии/разрешения/общественного достояния или верифицированное и применимое законное исключение. Статья 1274 ГК РФ об объёме, оправданном целью цитирования, не даёт общего разрешения автоматически выдавать главы для любых пользователей.

Для `unknown`/`restricted`/неподтверждённых rights — отказ в полном экспорте со ссылкой на причину; обычный поиск цитат не ломать. Для подтверждённого `licensed` и `permission_granted` читать **конкретные условия**, не делать вывод о PDF/аудио только по названию статуса. На каждом `start`, cache hit, выдаче signed locator и финальном download перепроверять active revision, withdrawal, текущие grants, audience, expiry и доступ к выбранной единице. Shared Slack = только `public_only`; никакой приватный файл в общий тред. Уже скачанный файл не может быть технически отозван — честно описать это в продукте.

Начальный тарифный дизайн (квоты и числа не утверждены владельцем): demo — ограниченный пробный экспорт, professional — больше единиц/приоритет, local historian/teacher — исследовательские пресеты и академическое оформление. Ни платный, ни профессиональный статус **не отменяет права на конкретный текст**. Прежде чем делать runnable P0, владелец утверждает минимальную матрицу source rights/entitlements, без ложного обещания произвольного chapter download.

## 6. Асинхронная операция P0 (логический контракт, не объявленный готовым MCP API)

Сохранять существующие authority/admission/receipts; не вводить новый брокер или вторую PG. Имена ниже **проектные**, до утверждения wire schema, а не утверждение существующих методов:

```text
selection.resolve(citation_refs[]) -> source/unit candidates, completeness,
   rights availability, edition + page labels, estimated volume
export.start(selected_unit_refs[], format=pdf, idempotency_key)
   -> operation_ref, queued/preparing/rendering/ready/failed
export.status(operation_ref) -> per-unit readiness, normalized error,
   progress/queue if known, download readiness
export.download(operation_ref) -> authorized bounded delivery / direct ticket
```

`citation_refs` резолвятся сервером в actor-bound контексте текущего ответа и accepted source provenance. Не доверять ID/страницам/rights, присланным клиентом. Если выбор неоднозначен — preview просит подтвердить реальную единицу, не выбирает ближайшие 20 страниц. Нельзя реконструировать исходную главу через `accepted_chunks`/search LIMIT: отдельный **bounded export read** в Kaggle PG берёт только выбранные span refs в одной консистентной версии. Не запрашивать оригинал целиком и не пересылать его на Dev. Авторизация на Dev, чтение/тяжёлая сборка рядом с PG на Kaggle; вне query/BGE hot-path, с ограниченной конкурентностью и без влияния на search p95. Cold-start использует существующий controller, не новый notebook на каждый PDF.

Жизненный цикл: idempotent exact selection + immutable accepted revision + effective rights scope + layout/render version. Повтор запроса с тем же ключом и другими параметрами = conflict; retry после потери ACK использует существующую операцию. `ready` только после проверенного PDF (bytes/MIME/readback), не по факту завершения Python. Короткоживущий private cache допустим; **не** копировать исходные страницы/целую книгу в постоянную Dev-БД. После рестарта безопасно повторить deterministic render с того же snapshot, если артефакт не подтверждён; неизвестный исход upload не означает запуск второго неконтролируемого Kaggle job. Срок жизни результата и клин-ап по действительным refs/потребителям; отказ/withdrawal отключает выдачу cache.

**Измеряемые целевые ориентиры, не SLA:** для прогретой сессии и 2–30 обычных текстовых страниц целевой p95 от старта до готового PDF — порядка 30 секунд; измерить реальный latency/CPU/RAM/PDF size/качество до фиксации. Cold startup, сложные таблицы и шрифты отдельно. Слишком большие сборки ограничивать ресурсным бюджетом и отдавать понятную ошибку/предложение нескольких пакетов — не делать деление текста посреди главы.

## 7. P1 · аудио, Kaggle и сравнение движков

### Что уже существует и что нельзя копировать вслепую

В `onedayonemasterpiece/wonderful-lections` есть `src/presentation/kaggle-scenario-audio-provider.mjs`, `scenario-audio-runner.mjs`, `presentations.audio.start`, `operation.get`, `presentations.audio.get`: Qwen/Qwen3-TTS-12Hz-1.7B-Base, reference voice, CPU Kaggle, chunk processing и асинхронная durable queue; исходная версия сценария/голоса закрепляется. Реальный путь и условия описаны в [WL longform incident](https://github.com/onedayonemasterpiece/wonderful-lections/blob/main/docs/reports/incidents/INC-2026-10-05-scenario-audio-longform.md). Это **реализация в соседнем продукте, не доказанная сейчас готовая shared TTS служба**.

Опыт эксплуатации: реальные задания 3400 слов падали, причина была и в pip dependency pin, и в сгенерированном Python `null` вместо `None`; longform удерживал модель в памяти, затем перешёл к batch child processes (не более четырёх chunks на процесс). Были transport 429 при продолжавшем работу job и непригодный промежуточный `ListKernelSessionOutput.log`; live progress появился через `GetKernelSessionLogsStream`. Зафиксирован progress 24/57 chunks, **не** конец прогона. До подтверждённого успешного longform real readback нельзя объявлять этот pipeline готовым к RKB.

[Сохранённый исторический longform baseline](https://github.com/onedayonemasterpiece/wonderful-lections/blob/main/docs/product/lecture-basic-jobs-20260905.md) — 50 chunks, 2585 слов, MP3 длительностью 1179.624 с. **1179.624 с — длительность получившегося звука, не замер времени синтеза.**

Рекомендуемая архитектура P1: **отдельный изолированный Kaggle CPU TTS slot/run** (не конкурирует за CPU/RAM с RKB PG/BGE и не меняет его query/readiness), управляющий контур — через существующие durable orchestration/identity, без «создать Notebook на каждый chunk». Перед выделением самостоятельного общего voice-service сравнить reuse существующего WL provider как библиотеки/контракта с сетевой службой; отдельный сервис оправдан только для двух реальных потребителей и при доказанной изоляции прав/очередей. Никакого silent fallback на модели/провайдеры. Входные данные для TTS — **проверенный авторский текст P0**, не ответ поиска, не сценарий, не LLM-пересказ. Право на озвучку — отдельное от права на PDF.

### Быстрый вариант: осмысленный A/B без выдуманной скорости

| Маршрут | Преимущества | Ограничения / гипотезы |
| --- | --- | --- |
| Qwen3-TTS 1.7B CPU на Kaggle | Контролируемый runner, RU/DE, потенциально низкая денежная цена за запрос, уже есть опыт WL | Холодный старт, установка/веса, длительная генерация, Kaggle лимиты, 429; длинный текст требует shards, проверку и restart |
| Qwen3-TTS 0.6B / GPU при разрешённой квоте | Потенциальная оптимизация latency, тот же класс модели | Не утверждать выигрыш без одинаковых русского/немецкого A/B, проверок качества и доступности GPU |
| OpenAI `gpt-realtime-2.1-mini` (Realtime API) | Streaming / короткая time-to-first-audio как исследовательская гипотеза | Не называть «бесплатно», transcript/style может отличаться от входа, платный облачный сервис, session/cost; не подменяет `/audio/speech` |
| OpenAI `gpt-4o-mini-tts` и `tts-1` | Старый прямой TTS API/быстрый streaming для коротких отрывков | **Deprecated, прекращение 06.01.2027** по текущей документации; нельзя основывать новое долгосрочное решение на них |

Источники: [Qwen3-TTS GitHub](https://github.com/QwenLM/Qwen3-TTS), [Kaggle notebooks limits](https://www.kaggle.com/docs/notebooks), [Kaggle GPU quota](https://www.kaggle.com/docs/efficient-gpu-usage), [OpenAI Speech guide](https://developers.openai.com/api/docs/guides/text-to-speech), [OpenAI Realtime mini](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini). «Безлимитная Qwen» значит отсутствие тарификации внешнего TTS за каждый запрос **только в смысле self-host**, а не бесконечный ресурс Kaggle: compute/quota/session/storage имеют пределы.

**A/B критерии (обязателен замер, без выдачи цифр из рекламы):** 2, 10, 30 минут RU prose, 10 минут DE, имена/топонимы/даты/сноски, cold start, warm time-to-first-audio, full completion wall time, RTF=compute_seconds/audio_seconds, цена/мин, кириллица/ударения, WER vs exact canonical text, пропуски/повторы при chunk joins, голос/подача (слепое сравнение), p50/p95 failure/recovery и readback. Realtime audio **не считать точной озвучкой**, пока контроль ASR/alignment + человеческое прослушивание не докажут буквальную полноту; исправления произношения идут во внешний pronunciation layer, оригинальный PDF text не меняется. Озвучка маркируется как синтетическая; клонирование голоса только при разрешении правообладателя голоса.

### Durable audio: временный dataset, не ещё одна основная БД

Кэшировать **успешно проверенные частичные chunks**, затем assembled MP3/M4B (предпочтение исходно MP3). Один приватный versioned Kaggle Dataset/controlled artifact store как **временный cache на дни/недели**, с manifest `source+revision+unit spans+canonical text digest+voice/profile+engine/model+normalization version+chunk plan+output codec`, SHA файлов, статусы completed chunks, explicit owner/tenant audience. Ранее проверенный chunk использовать повторно только при том же точном input/profile; partial после failure не перегенерировать.

Kaggle Dataset versioning сам по себе не поддерживает автоматический TTL для отдельного MP3. Официальный CLI поддерживает `datasets version --delete-old-versions` (удаление **старых версий целиком**, а не выборочно истёкших чанков), а также `datasets delete` для всего dataset. Эти действия могут сломать ссылки других активных jobs: отдельно проверить API/retention, references, private ownership, version churn и фактический результат удаления. [Kaggle CLI Dataset reference](https://github.com/Kaggle/kaggle-cli/blob/main/docs/datasets.md); [Kaggle dataset limits](https://www.kaggle.com/docs/datasets). Если безопасный private Dataset с требуемой retention недоступен — не объявлять его обязательным продуктовым storage до проверки, использовать разрешённое краткоживущее private artifact storage. Не публиковать книгу/голосовые samples/MP3 в публичные notebook outputs, логи, GitHub или общие Slack-треды. Отозванное право блокирует скачивание, даже если файл ещё существует до GC.

`queued -> starting -> synthesizing -> verifying -> ready|failed|revoked`, плюс `provider_wait` при временной недоступности чтения статуса. Persist exact Kaggle run/version/attempt/partial refs; 429/отвал связи при существующем RUNNING не означает `failed` и **не** порождает duplicate submit. Control heartbeat даёт UX progress, но authority — actual terminal provider status + verified bytes. После рестарта reconcile тот же handle; застрявшая очередь не должна блокировать PDF и быстрый поиск. Справедливость пользователей и лимит одновременных запусков под реальную quota.

## 8. Реализация и порядок принятия

**P0.A — data/rights gate:** научиться резолвить citation→unit; использовать существующие accepted article IDs; для глав — минимальная структурная привязка; доказать полное покрытие source spans и полный набор подтверждённых метаданных. Проверить, что конкретная лицензия/правовое основание разрешает выдачу *всей* выбранной единицы. Пока нет прав/границы/текста — возвращать явное unavailable, не генерировать.

**P0.B — reader + typesetter:** Kaggle-side read-only structural projection по pinned revision, простой безвекторный PDF renderer без подмены текста, ordered footnotes и unit boundary. Прогреть/test без частного корпуса с открытыми искусственными/тестовыми фрагментами. Зафиксировать независимую fixture на кириллицу, немецкий, 2 статьи на одной странице, длинную сноску, таблицы, оригинальную/печатную пагинацию.

**P0.C — UX/async/delivery:** multi-select citations, preview, idempotency, lifecycle, authorized bytes, cache-hit/withdrawal, справедливость и UX при холодном Kaggle. Проверить настоящий End-to-End по разрешённому тестовому изданию, downloadable PDF, точность текстового сравнения и метрики.

**P1.A — reuse spike:** воспроизвести WL longform только в согласованной TTS среде с тестовым текстом, собрать фактические time/quality/quotas, выбрать вынос vs shared module по измерениям. Не вмешиваться в RKB live Kaggle run или WL production.

**P1.B — durable audio:** отдельные права, jobs/fairness, resumable chunks/private short-retention Dataset, контроль текста/сегментов, провайдерные reconciliation и пользовательский status/download.

### Вопросы на утверждение владельцем (не останавливают написание спецификации)

2. **Неоднозначные границы:** допустимо ли показывать пользователю подтверждение диапазона при отсутствии оглавления, или только автоматически установленная целая глава?
3. **Тарифы/объёмы:** начальный лимит страниц/единиц в одном экспорте и нужны ли различные очереди/квоты для demo/professional/local_historian/teacher? Не закреплять числа до данных.
