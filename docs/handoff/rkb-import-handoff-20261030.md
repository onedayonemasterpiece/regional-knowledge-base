## 3. Решения владельца (не нарушать)

- Страницу читает модель. Никакого серверного OCR/VLM/LLM. Подсказку из текстового слоя PDF сохраняем, модель извлекает её сама.
- Транскрипция дословная (PR 561). Фрагменты ~256 BGE-токенов. **Жёсткий предел — 512 токенов на полный вход** (в инструкции после PR 610). Стандарт фрагментов — у RKB-Ответы. **Своих подсказок читателю не давать**, только инструкции MCP.
- Одно окно ведёт книгу целиком, один читатель на книгу. Путей «починки» в коде нет.
- Границы статей и глав (start и end) ставит модель по смыслу, а не детерминированный код. Из них собирается PDF статьи (PR 607/625/627).
- Порядок чтения страниц выбирает модель (PR 606): `previous_physical_page_index`, `next_cursor` — только подсказка.
- Импорт единый для всех форматов (PDF, DjVu, дальше веб).
- Kaggle — вычисления, Kaggle Dataset — хранение. Верхний уровень архитектуры не пересматривать. Yandex S3 — только еженедельный бэкап. Telegram — архив оригиналов, Kaggle сам скачивает по `telegram_original`.
- Требования экономить вес картинок нет. 256 KiB — пилотный бюджет кодировщика, а не лимит канала.
- **Время поиска — ориентир, ошибку из-за времени не отдаём** (PR 620/622).
- Дефектный скан (как физ.116 Albinus): различимое — дословно, остальное — `[?]`, `needs_review=false`. Книга входит в «100» с признаком неполноты. Механизм дефектов не строим.
