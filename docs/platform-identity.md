# One person across product resources

Active contract 2026-10-20. [Auth](auth.md), [MCP execution modes](mcp.md) and the [single handoff](prompts/rkb-scalable-kaggle-implementation-20261019.md) define implementation and acceptance.

One canonical platform/RKB person UUID is linked to verified provider+tenant+subject accounts. Products retain their own resource-specific grants, domain ownership and revocation. Display names/email are profile fields; professional weight and bibliographic author identity are not authentication.

Personal MCP, Slack/Dot and Mira route to that same person and fair admission. Dot→tools and Mira→tools are independent smart routes; neither is the other's identity or mandatory reasoning proxy. An executor service is recorded separately from the human author. Wrong binding triggers attribution review. Unlinking an account stops future access without pretending past correctly attributed contributions never existed.

The one canonical authority supports ephemeral read_query, durable_question/request and mutation/provider-effect. Ephemeral reads use RAM permits and an attempt request_id; they do not manufacture durable question/history rows or promise RESUME/resultSaved. Durable questions and effects retain verified dialog binding, atomic sequence, immutable input/outcome refs, receipts and current delivery rights. PH's own utterance recovery/checkpoint state remains intact even when one RKB tool call is ephemeral. Multiple clients/dialogs of one person never create multiple fairness shares.

The existing control index tracks unresolved mutations by canonical person and typed resource/scope dependencies across Dot/Mira/MCP. An intersecting pending/UNKNOWN write yields prior_write_pending with observed freshness at read start/delivery; shared-resource changes affect all applicable readers. Unrelated private-draft writes do not block accepted-book search, while unproven independence is treated as dependency. This cross-route check is separate from durable per-dialog order and adds no new journal; see [handoff §§5.2, 10.2](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Pass compact verified identity/resource/scope and auth/grant epochs through PH's typed provider and existing Dev admission to the outbound notebook WSS. Do not enumerate all allowed documents per request or trust client-supplied person/category/dialog fields. Kaggle checks current top-K source/derived-content eligibility; Dev checks scoped policy deltas against full source/variant/grant dependencies before delivery, including cross-book text/bibliography. Drop whole affected items and explicitly degrade the result, never return empty success after withdrawal. Incomplete/compacted policy evidence fails closed for the affected scope/result; cursor freshness alone is insufficient. Caches and continuation/context refs cannot grant rights. The remote-durable access barrier is distinct from pending PG withdrawal/public purge and their Saved/readback requirements; see [auth](auth.md) and [handoff §§6, 10.1](prompts/rkb-scalable-kaggle-implementation-20261019.md).

PH keeps exact ordered evidence refs in its existing private tool/utterance store keyed by `(session, turn_generation, tool_call_id)`, with current rights checked on reuse. Ephemeral checkpoints are asynchronous; a crash gap is explicit and never filled by pretending a fresh query reproduced the old answer's sources. Full disposition and committed-turn binding follow [handoff §10.4](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Do not build another IAM or expert account registry. Reuse the existing application identity/consent machinery and verified bindings; converging product sign-in must not require corpus reindexing. A token for another product is never accepted/forwarded as an RKB grant. Same-host machine integrations use narrow dedicated identities, not user OAuth or owner impersonation.

GEO-only content migration does not remove existing users, bindings, permissions, integration configuration or secrets. Public text/illustration policy does not expose a person's requests, private drafts or proof scans. Verify real multi-user route/revocation isolation; the former one-owner beta is historical, not the target user model.
