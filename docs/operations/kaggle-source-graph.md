# Accepted source graph at fresh11

New `source.import.v4` commands at the explicitly selected fresh11 tuple can
carry a deterministic `source_graph` section. The original GraphBundle choices,
existing source-key UUID rules, exact passage/page/region quote spans, aliases,
directional relation types and selected finding entity keys are retained. Facts
and graph entities do not require a narrative Story. Same spelling selects no
identity. Explicit reuse must pass native current owner/kind/source checks.

The new native effect preserves the SHA of the complete accepted payload. It
writes source graph projections, source facts, narratives when supplied,
activation, accepted ledger receipt and the existing read frontier in one
transaction. Retries use the same command; graph handling does not run a model
or enqueue extra encoding. Old v1/v2/v3 and original schema9 v4 remain unchanged.
Native history verifies each graph projection against the original accepted
command, alongside the existing source/story origin proof. A bare source ID or
raw graph row is insufficient.

Source-place metadata and independent POI facts remain source hypotheses.
References to Street Story or Cartography do not certify owner geometry, perform
an external mutation or copy an owner database. Retained legacy GEO manifests
keep their independent private owner gate and `legacy_unanchored` provenance.

The existing `graph_fetch` tool has one registration. A known retained GEO UUID
uses its private gate; accepted-source graph UUIDs use SourceReadGate. A failed
branch never falls back to another authority. Accepted-source graph pages expose
bounded entity representations, mentions, aliases and directional relations.
`entity_list` currently requires one exact accepted source ID, at most three
records per page. Whole-corpus graph search, kinds filtering, graph discovery,
post-import graph mutation and POI owner verification remain unavailable.
Native POI fact rows are persisted and readable through the fixed internal
`poi_facts` action; there is no new public MCP tool.

All reads use the configured OAuth/Participants authority and the same queue,
resource admission and final MCP issuance check. Current withdrawal, unknown
source writes, changed native history or revoked grants withhold delayed output.
Unit tests distinguish synthetic native observations from actual native fixture
receipts; no local test result is a deployment or production cutover claim.
