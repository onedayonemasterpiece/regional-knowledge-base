## Startup и attachment

**Первый запрос при холодном Kaggle:** любой авторизованный пользовательский MCP read не должен требовать, чтобы Dot или владелец предварительно вручную запустил ноутбук. При отсутствии READY existing controller атомарно создаёт/переиспользует один startup demand и reconcile UNKNOWN, затем выбирает живой owned run либо один новый разрешённый запуск, закреплённый Dataset restore/PG/BGE/WSS. MCP быстро возвращает typed pending/status/continuation, по готовности новый read идёт в тёплый ≤2s evidence budget. Не ждать cold startup внутри исходного tool call; не делать многократный kernels_push при socket drop. В существующем QUERY_RESULT v2 нет pending enum. В source branch PR #170 добавлена отдельная типизированная *MCP* оболочка `rkb.startup.v1` для cold `search/knowledge_search` и `startup_status`; исходная QUERY_RESULT v2 не изменяется. Для PR есть isolated fixture/WSS tests, но **реальный deploy/cold Kaggle Dataset→PG restore/полный runtime — NOT RUN**, а не продуктовый PASS.

1. Existing controller reconciles active/UNKNOWN, выбирает совместимый owned run либо сохраняет один launch intent и резервирует разрешённый slot. **Slug постоянный**, версия/run/nonce меняются; повторный push при неизвестном исходе запрещён. Code hash, launch-config hash и точный executed-source hash раздельны. Проверяются immutable bundle и фактические Linux architecture/ISA/libc/shared-library ABI.
2. Минимальный control runtime выполняет authenticated outbound WSS/HELLO **до** тяжёлых installs/PG restore/BGE load. Bootstrap instance ID отличает повтор той же версии; worker/connection generation — reconnect/controlled restart. Один WSS owner, HTTP pull и WSS не dispatch параллельно. HELLO не READY; Telegram use grant выдаётся только после проверки identity/lease, boot stages видны сразу.
3. Восстанавливает exact verified private Dataset base в PostgreSQL 17/pinned extensions, проверяет manifest/internal cursor и ordered remote tail с schema/function transitions. Bounded stages не блокируют control event loop. Один раз загружает resident PyTorch BGE-M3: 1024 FP32, input≤512, baseline CLS/L2/no-prefix; actual tokenizer backend закреплён. Нет per-request install/model load/spawn/compile или моделей на DevCoveer.
4. Проверяет fused QUERY: query encode + local dense/FTS/alias SQL + RRF + batch hydrate evidence/bibliography внутри Kaggle, без vector round trip на Dev. Actual SQL+dense readback и exact loaded hashes подтверждают READY. Snapshot upload, process liveness и vector counts недостаточны. Existing BgeQueue и read permits используют прежнюю authority.

Dot → RKB и Mira → RKB остаются самостоятельными маршрутами; Mira не вызывает Dot. Existing DevCoveer ASGI делает auth/admission/relay, а notebook использует только outbound WSS, без public listener. Database port остаётся внутри notebook. Credentials не входят в snapshot или public notebook output. Large files/accepted payloads передаются bounded byte transport по authorized refs.

## Reconnect и защита от повторов

При socket drop тот же живой notebook держит PG/model и повторяет handshake с jitter/backoff. Для durable jobs сохраняются bounded inflight results; RESUME сопоставляет job/claim/generation/result hashes. Same operation + same payload возвращает прежний outcome; different payload под тем же ключом — conflict. Ephemeral QUERY не входит в durable RESUME: deadline/turn/connection generation ограничивают его жизнь, late/cancelled result не выдаётся после reconnect и не запускается заново скрытым полным retry.

Новый attachment получает connection generation и fencing старого socket. Stale claim завершает соответствующее задание, а не убивает warmed worker. Revoked run больше не принимает новые authority-bound effects. Уже remote-accepted commands прошлого epoch остаются replayable.

Controller не запускает kernels_push только из-за потери socket. Когда Kaggle session закончилась, сохранение RAM невозможно: новая версия под тем же slug выполняет restore/warmup. Unknown launch reconciles по существующим launch IDs и доступной exact provider identity; latest-by-slug не доказывает исход. Не создавать серию notebook по timeout одной попытки.

**Статусы cold demand (PR #170, source/fixtures):** после OAuth/public_search клиент получает успешный MCP `pending` без вымышленных hits и стабильный `startup_ref`. Новый `startup_status` каждый раз заново проверяет права; после текущего full source-history/PG/BGE proof возвращает `ready`, и только тогда клиент делает *новый* read. Один ref сохраняется независимо от TTL конкретного run. При истечении heartbeat у прежнего READY/dispatched status сообщает `unavailable/provider_execution_unknown`, а owner+capacity остаются за UNKNOWN; ни прямой запрос, ни старые document jobs не запускают новую версию при заблокированном cold-start. Для повторных **достоверных** preparation errors действует конечный лимит 3 отдельных failed attempts — и при наличии `startup_ref`, и для исторических durable `document` jobs без него. Новый авторизованный `request_startup` присоединяется к существующему бюджету, не обнуляет уже произошедшие legacy failures. После лимита `status.state=blocked`/`reason=startup_retry_exhausted` и отказ от автоматического повторения, в том числе когда jobs продолжают стоять в очереди. Ручная recovery после устранения причины требует разрешённой операторской процедуры, а не нового локального цикла.

**Не путать provider version и session execution:** source/version match + `version_status=COMPLETE/FAILED` — диагностическое наблюдение, но без отдельного execution-qualified terminal proof нельзя освобождать run, reuse TG slot или делать replacement push. Код референсного launcher умеет сообщить `terminal_unverified`, но сохраняет UNKNOWN. Смерть уже выполненного полезного idle demand не считается новым спросом и сама по себе не перезапускает worker. Same-incarnation WSS ATTACH после heartbeat gap обновляет socket heartbeat и connection generation атомарно, но возвращает поисковую готовность лишь после fresh runtime proof; тестируется действительным ASGI WebSocket, не только вызовом Queue API.

## Быстрая итерация и SQL maintenance

До runtime работы установить и прочитать [kaggle-warm-debugging](../../.agents/skills/kaggle-warm-debugging/SKILL.md), зафиксировать pin/install/read receipt по handoff§0. Полный skill включён в репозиторий; он не выдаёт runtime authority и не требует отдельного notebook каждой итерации. Direct bulk/temporary Dataset cleanup и client effects — handoff§5.5–5.6.

Канонические правила — [handoff §5.4/6.6](../prompts/rkb-scalable-kaggle-implementation-20261019.md), проверки — DBG-1–13. Локально/CI сначала малый isolated PG fixture, read-handler rollback со stub-моделью и lost-ACK migration case. Затем один ограниченный разрешённый runtime smoke; обычные исправления идут в этот же run по exact artifact ref/hash через existing maintenance authority.

SQL/function patch применяется к живому PG с expected revision, writer fence и PG migration lock. Ledger повторно читается под lock, transactional DDL и migration record фиксируются одним commit. Несовместимая v2 закрывает новое принятие domain commands под v1 и ждёт recorded outcomes всех прежних accepted/sealed v1 commands, включая undispatched queue и UNKNOWN в исходной DB generation. Schema transitions и accepted commands replay в исходном порядке; модельные решения не пересоздаются. Не нужен новый HTTP RPC service.

Это требование к реализации: на аудированном NEW authenticated hot-handler activation ещё отсутствует, SQL replay её не заменяет. Горячо заменяется только совместимый stateless read handler после import/self-test/drain; при плохом candidate/первом probe остаётся прежний handler, model context не заменяется. Executor mutations меняется через migration barrier. Transport/lifecycle/model context требуют честного controlled worker restart; если модель в этом процессе, warmup повторится. Dependencies/cache pinned, не переустанавливаются при SQL/app patch. После apply readback loaded hash, schema, useful result и restart/model-load/download counters обязателен; файл на диске не доказательство загрузки.

Dataset нужен для checkpoint/крупного артефакта. Редкая замена PG — finite maintenance окно внутри той же notebook session; live PGDATA не подменять. Verified base+tail и recovery pointer сохраняются отдельно от active routing. Два PG clusters/catch-up — только при измеренной необходимости и ёмкости, не обязательный debug framework. Реальный GEO/accepted/Saved никогда не disposable; test fixture имеет immutable classification и не получает product routing/grants.

## Runtime и supervisor

Python — default bootstrap/transport/query glue и существующая authority над PG и одним PyTorch model. Precompiled Go, в том числе на DevCoveer, может заменить transport/serialization component; Rust — дорогую функцию либо компонент с воспроизводимой проблемой памяти/lifecycle. Память, deadlines, backpressure и control-loop isolation допустимы как основания native выбора нового компонента до доказанного CPU hot loop; проверенный native reuse не требует полного Python дубля. Native sidecar не является default; новый proxy, второй model или authority не добавляются, заменяемый путь удаляется. Один узкий вариант принимается по подтверждённому улучшению полезной задержки/ресурсов/отказов без регрессии quality, прав и recovery. Local IPC допустим с учётом его copies/serialization/backpressure, Python BGE child и дополнительного lifecycle; полный rewrite не нужен. ONNX/GPU/quantization требуют отдельной проверки numerical contract и retrieval gates. Native bundle собирается заранее; один build hash/ABI/protocol manifest и controlled rollout, без runtime toolchain download на каждый запуск.

Supervisor остаётся живым, получает exit status, постоянно и ограниченно читает stdout/stderr, не печатает query/private evidence. Для планового handover — drain, checkpoint и bounded PG shutdown; smart SIGTERM не должен бесконечно ждать pooled clients. Session kill/SIGKILL не гарантируют cleanup, поэтому durability следует remote intent/outcome contract, а не finally. Primary детали — [runtime assessment](../designs/kaggle-regional-knowledge-service-assessment-20261019.md).

Parent bootstrap — best-effort watchdog вне рабочего event loop, не второй authority. Он читает bounded local stage/lease record; только проверенный controller renew, не локальный heartbeat, продлевает lease. При control loss/конечном wall budget — bounded drain и TERM/KILL только своих process group/PID-start identities. Parent тоже может зависнуть. STOP/cancel ACK, child exit, TTL, отсутствие WSS и notebook deletion **не** terminal proof. Нужен свежий capability-проверенный provider status конкретной execution. До этого `termination_unknown`, capacity/TG slot удерживаются; доказанная Telegram authorization revocation разрешает отдельно перевыпустить session, но не объявляет compute остановленным. Не копировать events-bot cancel-requested→terminal или my-data-hub delete→absence как эти гарантии.

Required output inventory задаётся до операции; native output download проверяет exact version, все страницы, обязательные bytes/hash. Run manifest сверяется с этим ожиданием; отсутствие manifest не превращается в пустой success. Полезные результаты отправляются по мере готовности, не только в finally. PGDATA/models/secrets/scratch — вне auto-published output на фактически проверенном writable volume. Partial artifacts/UNKNOWN сохраняют refs; cleanup не удаляет принятые данные.

## Таймеры и ресурсные границы

Useful-idle — 30 минут от реального спроса. Авторизованный direct `search_adapter` обновляет существующую activity-запись при входе, как обычный MCP; ответ модели не требуется. Отозванный authority и служебный heartbeat полезным спросом не считаются. Writer lease, task claim, heartbeat/Ping, stage progress, source-cache idle и provider lifetime независимы. Keepalive не делает notebook вечным и не продлевает полезный спрос.

Frames, total buffers, inflight credits, handshake/send deadlines и retry windows ограничены. CPU encode, render, blocking DB/file/network operations вынесены из event loop. Control reads не используют BEGIN IMMEDIATE. После commit сигнал wakeup виден другим process; bounded reconciliation восстанавливает пропущенные notifications.

Query-first/read permit действует в общей admission authority для всех producers; ephemeral read не ставится за durable import head. Import/story encode, Torch intra/inter-op threads, PG pool/parallel workers и maintenance учитывают общий CPU/RAM/IO envelope; защищён минимум один search reserve. Исходные четыре Torch threads/один interop не означают дополнительные свободные ядра. Lexical/alias SQL идут параллельно encode, модель остаётся одна; не ждать permit внутри SQL write transaction. Число notebook runs ограничено проверенными независимыми Telegram sessions и Kaggle capacity по [configuration](../configuration.md), не увеличивается ради обхода CPU budget.

## Что сохраняется до ACK

Следующий ACK contract относится к mutations/durable jobs и явно принятым долгим requests. Raw DevCoveer spool: implementation defaults 4 часа/512 MiB с измерением до cutover. Early receipt pending. Final accepted/Saved требует доказанного внешнего покрытия exact intent/payload выбранным Dataset persistence/continuation; прежний online S3 tail не переутверждается молча под именем weekly backup; Saved также требует domain commit и remotely verified exact outcome/receipt. Ready groups ждут flush ≤1 секунды: это окно набора, не гарантированный cloud RTT. Ephemeral QUERY не ждёт fsync/remote journal или audit flush ни перед dispatch, ни перед result. Bounded async audit содержит refs/hashes/timings; overflow/loss виден отдельно и не означает потерю durable mutation. Read-result не называется Saved без отдельного durable save.

NEW уже содержит часть S3 seal/continuous manifest/CAS; это проверяемый reusable recovery protocol, не свидетельство готового Dataset-primary adapter. Большие base bytes идут direct Kaggle→recovery object по scoped key/epoch/expiry без global/delete credentials; Dev 512 MiB spool их не пропускает. Presigned URL не отменяется сам при epoch change: old-writer upload остаётся orphan без promotion authority.

Canonical replay не хеширует заново derived BGE floats/FTS/crops. Exact domain outcome сохраняется, projection dirty/rebuild и dense readiness идут отдельно; accepted BGE artifacts reuse. Уже delivered artifact bytes/hash/receipt не подменяются.

Control checkpoint 15 min; changed PG base 4 h или раньше по replay/byte pressure/planned handover; weekly independent-from-Kaggle Yandex backup подтверждённой Dataset version. Local raw GC после доказанного внешнего покрытия не ждёт old weekly baseline; remote tail остаётся для designated recovery chains и unfinished consumers. UNKNOWN/request/receipt metadata не expires вместе с raw body.

## Отчёт readiness и recovery

Показывать отдельно transport state, model revision/readiness, database schema/cursor, query probe, active passage/story coverage, effective retrieval mode, replay backlog и last remotely sealed seq. Public status не раскрывает credentials/private text/чужие drafts.

Проверки включают socket drop живого run, kill завершённой session с восстановлением, late duplicate result, wrong generation, duplicate connection, lost ACK, failed remote seal, failed Dataset processing и restore без нужного WAL. Для release действуют [protected gates](../mass-ingestion-readiness.md); качественный ответ в 2 s нельзя заменить быстрым enqueue.

[Прежние pull/claim/complete deployment details](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/a8cf41b50b8ccb62409d046d009d53c09d74b1d7/docs/operations/bge-kaggle.md) — исходный runbook. Новое развёртывание следует этому контракту и handoff, не восстанавливает прежний E5/Supabase runtime.

### API restart and import status

While the source restore coordinator is incomplete, an import status or finalize call waits before querying source tails. It must not instantiate the lazy native-history maintenance dispatcher ahead of the retained restore/checkpoint owner. After restore composition completes, the same ingestion resumes ordinary tail checks; accepted packet identities and Dataset durability are unchanged.

`indexing_status` is not supported by the Kaggle source profile. Any method unavailable in the source profile returns `tool_not_supported_in_profile`; this is not a notebook health probe. Use normal search/fetch results and the current ingestion status to verify accepted-page visibility.

### Planned API shutdown

The API finishes HTTP calls already accepted at the shutdown boundary before Uvicorn closes the outbound-worker WebSocket. This drain uses the existing graceful timeout; forced exit remains available. Incoming calls during listener/process startup and typed target-warming responses are measured separately from an interrupted accepted read. The native notebook, model and saved source cursor remain owned by the existing controller.

The official Slack Socket Mode client uses at most one second for its WebSocket closing handshake during API shutdown, preserving a shorter existing limit. Reconnect is disabled by the SDK before disconnect. This bounds transport closure after accepted HTTP calls have drained; it does not replace the durable event receipt/ACK path or cancel the native notebook. Logs distinguish `rkb_socket_close` start/completion and elapsed time.

### Book tool argument errors

Server-side MCP argument validation for `book_ingest` and `book_pages` returns `invalid_query/invalid_input`, `error_class=validation` and bounded field/type/length hints without input values. This precedes backend dispatch; it does not change import limits or reinterpret backend/output failures as rejected input. A client validating the published JSON Schema before sending HTTP must redact its own diagnostics too: formatting an outer `anyOf` error can otherwise include the complete source packet. The server boundary cannot sanitize an exception created entirely in that client.
