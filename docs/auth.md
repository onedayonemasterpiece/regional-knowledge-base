# MCP authentication and delegated identity

Target contract 2026-10-20; implementation and live client checks remain required. See [handoff](prompts/rkb-scalable-kaggle-implementation-20261019.md), [MCP execution modes](mcp.md) and [rights](rights.md).

## Application authority

Existing application-owned OAuth stays on DevCoveer. PostgreSQL/pgvector in Kaggle is a data plane, never the user OAuth provider. Do not derive issuer/JWKS/resource from Supabase configuration and do not restore Supabase Auth users/auth.uid() as the identity source.

Preserve authorization code + PKCE S256, exact resource/audience and registered redirect binding, consent, short access lifetime, refresh rotation/replay revocation, discovery and stable UUID subject. `RKB_AUTH_ISSUER`, `RKB_AUTH_JWKS_URL`, `RKB_RESOURCE_URL` remain explicit. No secrets in URL/log/repository. Existing grants/credentials are infrastructure, not excluded non-GEO content; do not reset them during content cutover.

Resolve verified provider+tenant/workspace+subject to the canonical RKB person. Email, display name, Slack mention, client-supplied actor/dialog ID and claimed expertise do not choose an actor. Categories/credentials/subject weight are versioned separately from capability grants. A mistaken binding puts affected attribution/support into review rather than erasing history.

## Data and route enforcement

Server-side permission is current person capabilities ∩ case/artifact scope ∩ delivery audience ∩ executor service grant/request fence where delegated. Use transaction-local verified actor context and non-bypass SQL roles for domain access; reset at transaction end and test pooled-connection actor leakage. No user bearer forwarding to PostgreSQL or another MCP.

Dev supplies compact verified actor/resource/scope and auth/grant epochs to the existing authenticated notebook channel, not a complete list of allowed corpus IDs. Kaggle applies the corresponding eligibility/scope policy during indexed candidate selection, then batches current checks for selected top-K dependencies; a final check does not replace filtering private content before ranking. An out-of-date authority projection cannot authorize output: satisfy the required epochs within the deadline or return an explicit unavailable/pending result. Recheck current authority at delivery; discarded stale/revoked output is not relabelled as successful evidence. Cached computation never grants access, and invalidation is not a replacement for this check.

Accepted active book text and bibliography have no owner filter. Public illustrations are a separate artifact class. Stripe quote/page scans require owner or verified demo/expert/local_historian with `scan_proof_read`; original PDF/DjVu rights remain independent. Private drafts, history/receipt replay and derived snippets recheck their dependencies. Shared channels do not union participants' private grants. Cache hits and delayed callbacks recheck withdrawal/revocation.

Scoped policy deltas are checked against each item's full source/variant/grant dependencies, including cross-book prose and bibliography. Drop the whole affected item and its display/continuation fields; mark remaining output `degraded/evidence_withdrawn`, even with zero items, never empty success. Unaffected reads continue. If delta history is compacted, provenance incomplete or current scope unproven, fail closed for that scope/result; a cursor alone cannot prove eligibility. Continuation and PH context refs never confer permission.

Revocation/withdrawal must make the existing authority barrier and exact intent remote-durable before confirming that new RKB access is blocked. This barrier does not wait for Kaggle availability. PG withdrawal and external public-output purge remain pending until their own commit/readback; do not report them Saved or removed early. All serving routes obey the same barrier. These are policy-mutation durability requirements, not per-read remote writes; [handoff §§6, 10.1](prompts/rkb-scalable-kaggle-implementation-20261019.md) remains authoritative.

Import/reprocess, participant administration and credential binding remain owner personal-route operations. A bot invoked by owner cannot bypass the expert-route ceiling. A case manager/owner does not automatically read another person's private draft. Exact selected-fragment publication requires its own capability and does not publish the rest.

## Delegated clients and services

Personal MCP clients use resource-bound user grants. Slack resolves the verified sender and invokes the same resource through a dedicated executor identity; Dot's credentials/author name are not substituted. Dot→tools and Mira→tools remain independent smart routes. Mira uses PH's typed target-resource provider→existing Dev auth/admission→the authenticated WSS initiated by the notebook, without another Dot reasoning turn or public notebook listener. Progressive capabilities stay in the existing live-interaction/PH adapter. Search-only adapter success is not multi-user acceptance.

One admission authority enforces three trusted operation modes. read_query has bounded RAM permits, request_id correlation, current scope/epochs, generation/deadline and min_data_seq, but no durable row, remote seal, RESUME or resultSaved. Durable_question/request preserves exact input/dialog context and result/hash/native ACK. Mutation/provider-effect preserves exact command/preconditions/remote intake, effect fence and receipts. Client labels cannot downgrade a mutation into read_query. A read's cancellation/disconnect is not cancellation or failure of an accepted mutation. The existing control index checks unresolved mutations by canonical person and typed resource/scope dependencies across Dot/Mira/MCP at read start and delivery. Intersecting writes return prior_write_pending with known freshness, including for every affected reader of a shared resource. An unrelated private-draft UNKNOWN does not block accepted-book search; unknown independence fails closed. Per-dialog turn order is distinct, and no UNKNOWN read record is created; see [handoff §§5.2, 10.2](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Versioned PH v2 carries status, freshness/min-cursor and continuation explicitly. Old evidence/mode success is emitted only if fully representable; otherwise use the old unavailable/error path, without dropping security/freshness information. A detail cursor is not permission and not a saved-result handle. PH's existing private tool/utterance store binds exact ordered evidence refs to `(session, turn_generation, tool_call_id)` and the committed turn; the ephemeral checkpoint is asynchronous, with explicit context_gap if a crash precedes persistence. Do not substitute new search results for missing old evidence. Read telemetry may be asynchronous and lossy in a separate bounded sink with counters; auth/grant changes, accepted request/effect receipts and PH voice-dialog recovery/checkpoints remain domain state. Neither request/evidence bodies nor tokens/private draft text go to notebook stdout or read logs. See [handoff §10.4](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Same-host Street Story/VibePublish calls use scoped technical identities on loopback/Unix socket, as required by the host integration policy. Kaggle uses authenticated TLS and constrained run credentials, not loopback to a different host or a full owner token. Existing credentials are never written into Dataset/control journal.

Fencing blocks stale new effects/results while preserving exact commands durably accepted in prior generations. Remote control recovery includes revocation versions and UNKNOWN; uncertain authority leaves writes/delivery closed until reconciliation.

## Client setup and acceptance

The intended public MCP resource remains `https://knowledge.kenigevents.ru/mcp`. Preserve existing confidential clients and public PKCE dynamic registration, exact allowlisted callback origin/URI validation and explicit foreign-resource rejection. A missing resource may bind only to the server's one configured resource under its existing compatibility contract; never infer another resource. Do not publish owner login credentials or ask experts to use owner consent secrets.

Verify each named client individually: actual non-owner sign-in, correct displayed identity, allowed research, denied administration/private cross-actor read, revoked link/grant during in-flight/cache-hit reads, pooled actor isolation and cross-route generation fences. Ephemeral reconnect must not replay old reads; durable reconnect must retrieve the same saved result and native hash ACK. Naming ChatGPT/Grok/Slack/Mira does not establish compatibility. Real Telegram sessions are provided independently for implementation; preserve owner-authorized session/run caps and never clone StringSession or evade provider account limits.

Verified demo/expert/local_historian assignment materializes the existing scan_proof_read policy grant with audit and category revision; demo expiry is inherited. Claimed categories grant nothing. Current capability/scope is checked at render time; explicit revocation is not recreated on read, and removing a category withdraws its policy-derived grant. No new IAM or per-image approval.
