# Публичная статическая страница дела о разногласии

**DISAGREEMENT-CASE-PAGE-001 · целевой контракт 20.10.2026.** Документ не подтверждает развёртывание. Общий [handoff](../prompts/rkb-scalable-kaggle-implementation-20261019.md), [дизайн дел](../design/rkb-disagreement-journal-design-20261018.md) и [ПМИ](../testing/rkb-disagreement-pmi-20261018.md) задают связанные правила.

## Назначение и постоянный адрес

Для дела формируется публичная страница без авторизации на существующем Astro-сайте events-bot-new/site, output:static:

`https://kenigevents.ru/raznoglasiya/<stable-slug>/`

Один case ID получает один постоянный случайный непрозрачный slug, не зависящий от title/revision. Это не пароль и не средство ограничения доступа. Любой обладатель ссылки может прочитать HTML. Не нужны login, OAuth, SPA, новый backend/API чтения страницы или отдельный scheduler. Страница демонстрирует исследование, не служит формой записи экспертных мнений.

В новом corpus дела создаются свежими импортами/исследованием. Старые книги, дела, Stories, ручные/личные drafts и contributions не мигрируют; переносится только GEO. Эта граница не отменяет историю новых дел и постоянство их URL.

## Содержание

Страница включает:

- исследовательский вопрос, case ID, даты/ревизию и статус рассмотрения; статус не является процентом истины;
- существенные позиции с границами периода/места/объекта и точными основаниями;
- книги, статьи и рецензии: название, edition/year, библиография, автор конкретной главы, отдельно редактор/переводчик и физическая/печатная страница;
- доступные иллюстрации/обложки, подписи и происхождение; отсутствие изображения не мешает прочитать текст;
- профессиональные материалы и аргументы с разрешённым публичным display name/регалиями, provenance и версией;
- индивидуальные мнения, модельную сводку и поддержанную людьми exact revision как разные результаты;
- current_conclusion_revision и last_supported_conclusion_revision с объяснением изменений; поддержка не переносится;
- открытые вопросы, следующий полезный шаг и связанные дела;
- реальную VK-ссылку только после подтверждённой публикации, а не обещанный будущий URL.

Все active accepted book text и bibliography доступны без per-book owner ACL; принятые иллюстрации публичны. **Страница/полоса proof не равна иллюстрации:** существующий scan_proof_read предназначен owner/demo/expert/local_historian, не анонимному посетителю; full PDF частный. Публичный пакет может использовать допустимую текстовую цитату с локатором и общедоступные illustrations, но не публикует scan proof, private originals или личный draft как обход grant. Source withdrawal, состояние принятия и revision проверяются перед export/build. Неизвестный или отозванный материал не становится открытым после удаления ссылки.

Частные drafts, закрытые внешние материалы и непубличные данные участников не входят в HTML, build input, JSON, OpenGraph, assets, sitemap или производный пересказ. Частная роль автора не превращается в общедоступную из-за участия в деле. Публичная атрибуция отдельно согласована. Демо на синтетическом материале явно помечено; реальные отсутствующие детали не выдумываются.

Если страница включает Story, она показывает доступный **сохранённый Variant.body** или помеченный excerpt с exact ref; title/summary/rating/bibliography не выдаются за рассказ. Case summary сама по себе остаётся исследовательской сводкой, не Story.

## Export, сборка и жизненный цикл

Existing disagreement_export(kind="case_static_page", case_id, revision) формирует **один versioned RKB export bundle**: типизированный безопасный snapshot, manifest и разрешённые asset refs; case/revision, постоянный slug, digest, позиции/evidence, разрешённые source metadata/images/contributions/conclusions/links и dependency revisions. Не передавать секреты, приватные object keys или исходный PDF в site build. Exact snapshot и desired revision/generation позволяют reject устаревшую сборку.

Существующий events-bot-new/site Astro SSG/build принимает этот versioned bundle и публикует его через обычное хранилище/CDN, без второго site/export pipeline. Повтор fingerprint — no-op; поздний build не перезаписывает новую редакцию. MCP get/export возвращает public_page.state, url, published_case_revision, published_at и last build status. **При первой публикации URL появляется только после независимого HTTP readback именно published URL: реальный HTML содержит ожидаемый case/revision marker.** Успех build/загрузка bundle сами по себе не подтверждают опубликованную редакцию.

При pending/failed обновлении прежняя доступная версия сохраняется как last-good с её реальными revision/date и честным статусом обновления. Это действует только пока её материалы разрешены. **Withdrawal/revocation требует удаления или безопасной замены/tombstone и проверки фактически выдаваемых URL/assets**, а не вечного сохранения запрещённого last-good. Исход подтверждает HTTP readback опубликованной страницы с ожидаемым revision/tombstone marker, assets и MCP state. Purge применяется только при реально доступном подтверждённом API; его отсутствие нельзя заменить обещанным purge proof. Если фактическая выдача ещё содержит старый отозванный output, revocation остаётся BLOCKED/незавершённым независимо от успешного build. Ошибка остаётся видимой, не называется success. Нельзя гарантировать удаление уже сделанных сторонних копий.

Noindex/исключение из sitemap допустимы для демо, но не заменяют публичную редакционную проверку. Название, metadata и preview подчиняются тем же правилам, что основной текст.

## Десктоп и телефон

На десктопе позиции удобно сопоставляются в колонках; на телефоне остаётся одна колонка без горизонтального скролла. Весь смысловой текст доступен без JavaScript, с клавиатуры, при увеличении шрифта и длинных именах/цитатах. Обложки не вытесняют источниковую подпись, отсутствующие изображения имеют текстовую замену. Длинные аргументы не пропадают из-за обрезанного preview.

## Приёмка

ПМИ KB-49…55 проверяет реальный URL без login/cookies/JS, desktop/mobile, атрибуцию, все существенные позиции, current/last-supported, отсутствие приватных assets, только подтверждённый VK link, один slug при retry/update и first publish readback. Дополнительно проверить поздний stale build, публичную иллюстрацию против закрытого scan/full PDF, source withdrawal до build и после publish, фактический HTTP output после отзыва, проверяемый purge только при наличии API и last-good только при сохранённых правах. Наличие макета, зелёного unit test или guessed URL не является публикацией страницы.

Astro — обязательный feature gate всего проекта. Core cutover, feature flag или временно выключенный сайт не дают PASS Astro: до реальной bundle→site build→published URL/revision readback проверки статус NOT_RUN/BLOCKED сохраняется. Mira/VK также имеют отдельные обязательные gates; поэтапная поставка не сокращает scope.
