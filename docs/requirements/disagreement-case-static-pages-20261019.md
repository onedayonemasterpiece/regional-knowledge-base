# Требование: публичная статическая страница дела о разногласии

## Применение в переработке 19.10.2026

Нормативный целевой контракт: [единый файл агенту](../prompts/rkb-scalable-kaggle-implementation-20261019.md) и [архитектура](../designs/rkb-scalable-kaggle-architecture-20261019.md). Текущий runtime ещё не перенесён этой документационной задачей.

- Один PostgreSQL/pgvector corpus в Kaggle, BGE-only (1024 FP32 baseline, exact pinned BGE input≤512); небольшой durable control journal на DevCoveer.
- Прямой исходящий WSS notebook→existing DevCoveer ASGI с двусторонними заданиями/результатами, durable ACK/RESUME и одной BgeQueue authority. Старые polling/локальный E5/Supabase инструкции не целевой deployment.
- Fresh MCP import книг; перенос только historical/cartographic layers и согласованных зависимостей, со stable IDs/provenance и проверенным reanchor. Ручная работа не уничтожается из-за отказа от старого corpus.
- Source-bound facts/dates/observations сохраняются без обязательной Story; эпизод/досье/Variant/private draft/independent case различаются. Один persisted research workflow, bounded compose, без квот и выдуманной драматургии.
- Поиск accepted active book text и bibliography без per-book owner ACL; current withdrawal/revision, pixels/original/private draft grants и delivery audience остаются обязательными.
- One canonical person/request/dialog, fair admission и confirmed result/hash ACK; Мира в PH расширяет existing typed adapter, не создаёт отдельный voice/IAM/queue.

Численные protected gates сохранены: backend p95≤1000ms, MCP p95≤1500ms/hard2000ms, BGE Hit@5≥85%/@10≥90%, RU→DE@10≥85%, ≥30 held-out families, ≥100 sources/100000 chunks, storage≤80% steady/≤90% peak. Документ не является доказательством PASS.

## Приоритет дополнения к исходному дизайну

Документ перенесён из PR142, commit `9d56b10c65d7c867f47f3d9f77fc002d60278b46`; исходные исследовательские, экспертные, публичные и MCP сценарии сохранены. Это спецификация, не свидетельство deployed implementation.

При конфликте execution-решений применяются: PG вместо старого SQLite/Supabase corpus; E5 удалён; единый research frontier для stories/cases/needs/POI; activation+durable continuation атомарны и не ждут экспертного консенсуса. Прежняя «фаза2» — этап того же saved workflow, не второй независимый полный scan. Existing BgeQueue/PR151 request lifecycle расширяются WSS; title/pair hash не определяет case identity.

Current/last-supported conclusions, exact human endorsement, private drafts, participant profiles/weights, source requests/reviews, VK editorial queue/whitelist, subscriptions, truthful readback и permanent Astro URL остаются обязательными. Страница сохраняет last-good при failed update; до первой успешной публикации URL не выдумывается. Новое public accepted text search не открывает scan pixels или закрытые private contributions.

Численные SQL/transport/retention параметры исходного текста ниже применимы только к старому checkpoint и сверяются с новым handoff. Датированные evidence и ещё не выполненная ПМИ не переименовываются в PASS.

## Продуктовое требование

У каждого оформленного дела о расхождении должна быть возможность выпустить **читаемую статическую HTML-страницу**, доступную **без авторизации, логина, аккаунта, cookies и отдельного backend**. Страница предназначена для публичной демонстрации, чтения и обмена ссылкой со специалистами; корректно работает на десктопе и смартфоне.

Адрес предлагается: `https://kenigevents.ru/raznoglasiya/<stable-random-slug>/`. Реальный slug создаётся однократно при первом экспорте/подготовке дела, хранится рядом с case ID и **не меняется** при новых аргументах, версиях заключений и публикациях. Он может быть непрогнозируемым для удобства распространения по ссылке, однако **не является механизмом защиты или секретом, гарантирующим конфиденциальность**: страницу вправе открыть любой, получивший URL, включая поискового робота.

**Не строить:** OAuth/login, пароли, одноразовые коды для просмотра, проверку роли при открытии HTML, signed links, клиентскую загрузку закрытого дела, отдельное SPA, новый сайт и сервер для этих страниц.

### Содержание страницы

На одной странице в осмысленном порядке отображаются:

1. **Заголовок, формулировка предмета дела**, краткое объяснение, почему версии расходятся; ID дела, дата первоначального открытия, дата последнего опубликованного обновления.
2. **Текущий статус исследования**: открыто, требует источников/сверки, обсуждается, имеется предварительное заключение, приостановлено/архивировано. Нельзя выводить «доказано» только потому, что модель предложила версию.
3. **Сравниваемые позиции**: чьи утверждения, период/контекст и чем именно различаются; доказательства и существенные ограничения.
4. **Книги, статьи, рецензии и другие разрешённые публикации**: обложки/миниатюры, если их показ правомерен; иначе аккуратная типографическая карточка без изображения. Авторы/соавторы/редакторы с корректными ролями, название, дата, издание, том/выпуск, страница/глава, библиография и доступная цитата.
5. **Дополнительные материалы профессионального сообщества**: аргументы, новые источники и содержательные поправки в хронологическом либо тематическом виде; отображаемое имя/публичные регалии/роль предоставившего материал, если они предназначены для публикации; иначе нейтральная атрибуция. Прямая реплика человека и краткое модельное изложение не смешиваются.
6. **Предварительные выводы**, если имеются: модельная сводка отдельно от индивидуальных и явно поддержанных профессионалами заключений; текущая редакция и дата, что пока неизвестно, какие свидетельства могут изменить оценку. Если заключения нет, так и написано.
7. **Переходы**: реальная ссылка на опубликованное обсуждение VK, если пост существует, и дата/статус обсуждения; ссылки на только те оригиналы/иллюстрации/другие дела, которые опубликованы для общего чтения. Планируемый VK-пост не получает выдуманного URL.

Страница отражает **публично разрешённую проекцию дела**, а не базовую запись целиком. Закрытые документы, сканы, неразрешённые для показа обложки, частные черновики, скрытые участники и их комментарии, непубличные имена/регалии/доказательства или выводы, раскрывающие закрытые сведения, **не экспортируются в HTML, JSON, метатеги, OpenGraph, sitemap или изображения**. Это проверка допуска материала на этапе экспорта **для публикации**, а не система авторизации просмотра страницы. Для демо возможен отдельный открытый образец с явно помеченными вымышленными данными; он не должен выглядеть как подлинное исследование.

### Работа со страницей и визуальная структура

- **Desktop:** понятная шапка дела, навигация по разделам, две колонки для сравнений версий и компактные карточки источников с обложками, далее обсуждение, хронология и выводы.
- **Mobile:** одна колонка, читаемая типографика, изображения по ширине, понятные переключения разделов, касательные цели удобного размера, без горизонтального переполнения. Одна и та же смысловая структура и данные, а не урезанный «мобильный пересказ».
- **Без JavaScript:** основные текстовые доказательства, источники, позиции и заключения доступны в исходном HTML; ссылки и навигация работают. Не требуется подключать РКБ или Slack при открытии.
- При отсутствии обложки/иллюстрации карточка источника остаётся полноценной. Имена и сведения об авторах не выдумываются; метка «автор не установлен» допустима.
- Изменение дела показывает **версию опубликованной сводки** и «обновлено ...»; зафиксированная ранее позиция или поддержка не переносится автоматически на новый текст.

### Производство HTML без новой инфраструктуры

В РКБ добавляется узкая публичная проекция `disagreement_export(kind="case_static_page", case_id, revision)` с проверенными открытыми материалами; версия схемы, canonical case ID, stable slug, snapshot digest, время, публичные источники/изображения/вклады/выводы/ссылки. Экспорт не содержит URL приватных object-store файлов и не запускает построение сайта сам. Публичный пакет проверяется при формировании, а не при открытии страницы.

Сайт использует **существующий** Astro SSG в репозитории `events-bot-new/site` (`output:"static"` уже установлен), например маршрут `site/src/pages/raznoglasiya/[slug]/index.astro` с `getStaticPaths()`. Утверждённый пакет встраивается как статические данные в уже действующий процесс сборки/публикации, использующий Kaggle static-site builder и Yandex Object Storage/CDN. **Никакого нового сайта, БД, API для чтения страницы, OAuth или собственного планировщика.** Повторная сборка при одинаковом fingerprint — no-op; содержательные изменения могут войти в обычную следующую сборку с известным состоянием ожидания.

MCP `disagreement_get`/ `disagreement_export`/ `disagreement_discussion` возвращают `public_page: {state, url?, published_case_revision?, published_at?, last_build_id?}` либо узкий эквивалент. **Ссылку возвращать только после действительного подтверждения публикации статического HTML и readback**, не после подготовки пакета или запуска сборки. До первой успешной публикации при `pending/failed/unpublished` не придумывать рабочий адрес. Если обновление ранее опубликованной страницы pending/failed, возвращать её проверенный last-good URL вместе с `published_case_revision`; не объявлять новую ревизию опубликованной. Один case ID соответствует одному постоянному slug; при очередном выпуске той же страницы URL сохраняется.

Если построение нового выпуска не удалось — действует **последняя успешно опубликованная версия**, показывающая своё время/ревизию; задача видна владельцу, но не объявлена обновлённой. При отмене публичности/ошибке прав предусмотрены удаление/замена опубликованного файла и связанных public media, invalidation CDN и проверка исчезновения ранее раскрываемых фрагментов. Это санитария опубликованного контента, не авторизация посетителя; нельзя обещать удаление копий, уже сохранённых третьими лицами.

**Поисковые роботы:** для первых демо-досье можно использовать `noindex` и не добавлять страницы в sitemap; это не защита и не условие просмотра. Открытое индексирование включать отдельно, когда контент готов для публичного представления. Текст и превью уже сгенерированы статически и не должны содержать скрытых источников независимо от `noindex`.

### Критерии приёмки

- Дело имеет один постоянный slug и открываемый URL на `kenigevents.ru`. Он возвращается через MCP только после readback опубликованного файла.
- Десктоп и мобильный браузер показывают все основные разделы, корректные обложки/текстовые замены, авторов с ролями, варианты, аргументы и статус; отсутствие данных не ломает экран.
- Страница полностью читается без входа и без JavaScript. Никакие сведения, не допущенные к публичной публикации, не попадают в её HTML, изображения и метаданные.
- После нового общественного аргумента страница обновляется с тем же URL и версией; ошибки сборки сохраняют last-good и честный status.
- При снятии страницы с публикации проверяется удаление/замена в Object Storage и CDN и отсутствие ссылок на снятую версию в MCP.
- Реальный VK URL отображается только после подтверждённого поста; подтверждение человеческого заключения не возникает из модельного пересказа.
- Проверка интеграции не выполняет импорт книг, не изменяет исходные чанки, не требует запуска отдельного живого сервиса РКБ при просмотре и не ослабляет действующие mass-ingestion/BGE требования.

**Не реализовано:** эта спецификация не означает, что страница, статический экспорт и MCP public_page уже опубликованы.
