# RKB: простои импорта 29–30.10.2026 — разбор по причинам

Требование владельца (30.10): импорт должен идти **без поддержки кодового агента**. Единичные зависания не чинить вручную — устранять причину, чтобы инцидент не повторился.

Итого за сутки около 15 ч простоя при ~20 стр/ч чистого чтения — больше, чем само чтение.

## Общая причина

Цикл «следующий ход читателя» держится на трёх ненадёжных опорах:
1. **Добровольный отчёт модели** как единственный сигнал «ход закончен».
2. **Процесс в сессии агента** (или ручная передача между агентами) как водитель цикла.
3. **Установка слитых исправлений агентом-оператором**: нет оператора — исправление ждёт.

## Системное исправление (минимум, без нового сервиса)

1. **Один долговечный водитель импорта** — скрипт RKB-Импорт (PR 640) как systemd user unit под `dev` (linger включён). Состояние на диске: назначение книга↔окно, последний job, `request_id`. Переживает reboot и перезапуски агентов. Ручных передач окна между агентами больше нет: отладочные действия оператора не меняют назначение, водитель продолжает после них сам.
2. **Завершение хода — по фактам, а не по отчёту модели.** При `unconfirmed` водитель вызывает `chatgpt_reconcile` (Launcher PR 45: маркер задания + законченный ответ → `page_completed`) и продолжает. Если доказательства нет — `read_reply`; ход не закончен — ждать.
3. **Сторож прогресса внутри того же водителя.** Признак — нет нового принятого stage по `book_ingest(status)` больше 20 минут при активном назначении. Действия: сверка → продолжение; Kaggle остыл — разбудить штатным status/startup. Не помогло за 2 попытки — одно сообщение в тред с фактом (без человека в цикле, только уведомление). Без второго сервиса.
4. **Слитые исправления хоста ставятся без агента.** Это вопрос владельцу: допустима ли автоматическая установка host-only компонентов (relay Launcher, API без native) из `main` после зелёного CI — существующим deploy-скриптом по таймеру? Без этого любое исправление ночью ждёт оператора.

Владелец исправлений: 1–3 — RKB-Импорт (ревью Opus, установка Шкипер); 4 — решение владельца, затем Шкипер.

## Приёмка

Ночь на двух окнах без участия агентов: прирост Saved за ночь; ни одного простоя дольше 20 минут, кроме времени холодного старта Kaggle; проверено искусственным `unconfirmed` (модель не прислала done) и рестартом процесса водителя.
