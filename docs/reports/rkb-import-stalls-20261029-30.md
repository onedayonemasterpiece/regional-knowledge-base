# RKB: простои импорта 29–30.10.2026 — разбор по причинам

Требование владельца (30.10): импорт должен идти **без поддержки кодового агента**. Единичные зависания не чинить вручную — устранять причину, чтобы инцидент не повторился.

Итого за сутки около 15 ч простоя при ~20 стр/ч чистого чтения — больше, чем само чтение.

## Общая причина

Цикл «следующий ход читателя» держится на трёх ненадёжных опорах:
1. **Добровольный отчёт модели** как единственный сигнал «ход закончен».
2. **Процесс в сессии агента** (или ручная передача между агентами) как водитель цикла.
3. **Установка слитых исправлений агентом-оператором**: нет оператора — исправление ждёт.

## Дизайн (решение владельца 30.10, заменяет прежний вариант с водителем и сторожем)

**Живость окна видна по его операциям в RKB, а не по странице ChatGPT.** Читатель делает `book_pages`/`book_ingest` примерно раз в 1–3 минуты на каждый разворот. Правила простые:

1. **Нет ни одной операции по этой книге 20 минут — окно мёртвое.** Ждать нечего, сразу новый ход в новом чате по тому же ingestion. Новый чат начинает с `book_ingest(status)`; принятые страницы сервер повторно не примет, так что дубля текста не будет.
2. **Окно ChatGPT живёт не больше ~1,5 ч.** Это не сбой, а свойство: ход заканчивается — сразу следующий.
3. **Ответ на странице закончился** — сразу «продолжай» в тот же чат.
4. Остановка только при «книга дочитана» или настоящем блокере из `status`. Тогда одно сообщение в тред.

**Кто это делает — без агента.** Задание «импортировать книгу X» даётся Launcher один раз, дальше он ведёт его сам по этим правилам. Launcher и так работает постоянно и переживает перезагрузку. RKB отдаёт в `book_ingest(status)` время последней операции по ingestion: из него Launcher видит «20 минут тишины». Отдельного скрипта-водителя, ручных передач окна и зависимости от `chatgpt_report(done)` нет.

### Как Launcher узнаёт состояние книги (замыкание дизайна)

Launcher не ходит в RKB как пользователь и не читает страницу ChatGPT, чтобы судить о живости: страница ненадёжна (30.10 05:40 чтение окна не вернулось за 15 мин). Источник правды — RKB.

- **Канал:** relay Launcher и API RKB работают на одном хосте. Запрос по loopback `127.0.0.1` к существующему API RKB по [политике интерсервисных подключений](https://github.com/onedayonemasterpiece/codex-devcoveer-mcp/blob/main/docs/operations/local-service-connections.md). Без публичного адреса, OAuth и браузера.
- **Учётная запись:** отдельный технический principal `launcher-import-watch`, **только чтение** и только активности импорта. Секрет — в защищённом конфиге relay, отзывается в RKB.
- **Метод:** `GET /internal/import/activity?ingestion_id=…` → `{state, next_action, last_operation_at, accepted_pages, next_cursor}`. `last_operation_at` — время последней операции читателя по ingestion (`book_pages`/`book_ingest` любого вида), берётся из существующего журнала операций. Эффектов нет, идемпотентность не нужна.
- **Опрос:** раз в 5 минут, только для активных задач «вести книгу». Недоступность RKB (рестарт, холодный Kaggle) — это не «окно мертво»: отсчёт 20 минут идёт только при ответе RKB `state=staged/continue_pages`.

### Задача «вести книги» в Launcher

- Вход: чат-шаблон продолжения и **упорядоченный список книг**: ingestion_id или локатор `telegram_original` из сохранённого списка 32. Для пилота — две задачи, по одной на окно, книги разные.
- Правила 1–3 выше. Книга считается дочитанной **по RKB** (`state` чтения завершено), а не по слову модели. Дочитана — новый чат со `start` следующей книги списка; повторный `start` идемпотентен (PR 639).
- Два новых чата подряд без единой новой операции в RKB — одно сообщение в тред задачи с фактами. Задача остаётся активной, новые чаты не плодятся чаще раза в 20 мин.
- Один активный чат на задачу — существующий запрет Launcher на второе продолжение.

Что снимается: отдельный скрипт-водитель (PR 640), сторож прогресса, сверка как основной путь, вопрос об автоустановке.

Остановки из-за установок новых версий Kaggle — отдельная тема. Их не допускают 636/637 (preflight перед rollout) и drain-граница.

## Приёмка

Ночь на двух окнах без участия агентов: ни одного простоя дольше 20 минут, кроме холодного старта Kaggle. Проверить: окно, замолчавшее без done; окно, прожившее до потолка.
