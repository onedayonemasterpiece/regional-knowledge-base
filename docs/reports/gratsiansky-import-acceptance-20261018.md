### Почему derived rechunk не является поддерживаемым исправлением этих дефектов

Проверены действующий tool contract и исходные proof constraints:
- rechunk разрешён для **неизменного** принятого источника и требует exact source/geometry/illustration identity;
- StageChunkInput принимает region_refs либо source-backed span_refs, не произвольный исправленный chunk text;
- StageRegionSpanRef привязан к original source_text и его SHA-256;
- stage_graph validator требует сохранения каждого непробельного source codepoint в совокупности spans, иначе `uncovered source span text in region`;
- несовпадение текста с точным span даёт `source span text drift`.

Поэтому удалить «П» выборочным пропуском символа нельзя без нарушения proof/coverage; изменить bbox в derived-only revision нельзя без нарушения source geometry identity. Это **contract-level blocker**, не якобы полученный отказ реального rechunk запуска: такой заведомо несовместимый запуск не делался.

Нужна штатная source-layout revision с исправлением по оригинальному изображению. Оригинальный attachment локально есть, но blind reprocess при неизвестном состоянии архива не запускался; допустимый recovery route требует совпадения зарегистрированных SHA-256, формата и числа страниц. Авторизации или учётные данные не менялись.
