# Ограниченный прогон RKB перед следующей книгой

Run: RKB-20261016-2023. Проверки начаты 16 октября 2026 в 20:23 UTC. Среда: действующий авторизованный MCP, без нового импорта, мутаций корпуса, перезапусков или нагрузочного теста. Основа: [ПМИ](../testing.md).

## Решение

**Полный «всё исправно» не подтверждён.** Доступ к существующим источникам работает, но обнаружены пропуск релевантного фрагмента и деградация смыслового поиска готовых историй. Следующий одиночный импорт допустим как контролируемый диагностический прогон, не как уже принятая эксплуатация. Для обещания надёжного поиска необходимо устранить и повторно проверить найденные дефекты.

## Программа этого запуска

1. Проверить фактический результат уборки и сохранность уникальных изменений.
2. Проверить каталог, активные редакции, профиль и обязательный индекс.
3. До поиска зафиксировать свидетельства и вопросы по шести группам фактов двух книг; проверить точные формулировки, перефразы и RU→DE. Это диагностическая выборка, не независимый holdout.
4. Проверить чтение сохранённых историй, их источников, графа и связи с POI; отдельно проверить смысловой поиск историй.
5. Записать задержки, ошибки и ограничения; не заменять проверку новой активации чтением старых записей.

Hit@5 = 10/11 (90,91%) среди полученных ответов; подтверждённое покрытие всей программы 10/12. Ответы содержат по восемь результатов: полноценный Hit@10 не измерен, Hit@8 = 10/11. Одна книга: 4/5 выполненных вопросов, другая: 6/6, включая 3/3 RU→DE rank 1.

Для пропущенного свидетельства отдельный fetch подтвердил существование актуального gold. Три первых найденных результата не отвечают на заданный вопрос. Это воспроизведённый промах, не отсутствие материала в корпусе.

## Открытые дефекты и следующий шаг

- RKB-LIVE-01: смысловой поиск историй недоступен, fallback не обеспечивает нахождение известной истории. Проверить предусмотренный контракт vector worker и ранжирование, затем повторить естественные запросы.
- RKB-LIVE-02: смысловой вопрос по книге пропускает ожидаемое свидетельство. Проверять идентичность актуального chunk, ранжирование и соседние формулировки на нескольких книгах; не подгонять по одному примеру.
- RKB-LIVE-03: задержки end-to-end требуют отдельного измерения с явной границей public MCP. Не выдавать backend latency за полное время ответа.
- RKB-LIVE-04: для принятия целой истории требуется полное собственное свидетельство каждой proposition, не только структурная валидация короткой цитаты.

Следующая книга/статья: один исходник → просмотр всех страниц с текстом/иллюстрациями/примечаниями → stage/validate/finalize → required BGE coverage → выборочный retrieval → source-grounded stories/entities → reconciliation → журнал результатов. Проверять всё в одном пользовательском сценарии, сохраняя pending состояние и не заявляя готовность по одному finalize. Новая книга не должна затирать незавершённые старые импорты.
