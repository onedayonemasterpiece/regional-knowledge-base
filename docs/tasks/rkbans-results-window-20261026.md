# Задание «Выдача»: различимые результаты поиска и пределы окна до 10

Заказчик: RKB-Ответы (Claude). Основание: PR 510 §3.3, §7, §11 п.1–2; PR 519 (пилот). План: [rkbans-retrieval-plan-20261026.md](rkbans-retrieval-plan-20261026.md).

## Цель для человека
Модель, отвечающая человеку, видит в выдаче не три одинаковых «Кёнигсберг в Пруссии…», а «Фриц Гаузе. Кёнигсберг в Пруссии (1994), с. 141» — и может выбрать, что прочитать. И у команды появляется возможность честно измерить, помогают ли 5/8/10 результатов вместо 3.

## Факты (origin/main 7161986f)
- `src/regional_knowledge/kaggle_public_backend.py:43-46` — `_evidence_title` берёт только `catalog.title`; locator (`pages 141`), автор и год уже есть в `item.metadata`.
- Пределы окна: `kaggle_protocol.py:82` (`evidence_limit … le=5 = 3`), `kaggle_public_backend.py:425` (`limit=3`), `kaggle_search.py:112-114` (`1 <= top_k <= 5`), SQL hydrate `candidate_ids[1:5]` (`sql/kaggle/001_search.sql:92`, `003_search_scope.sql:65`), `QueryResult.evidence` ≤ 5.
- Диагностический путь `acceptance_search` (`kaggle_search.py:80-93`, `observe=True`) собирает до 30 id (dense-10 ∪ lexical-10 ∪ fused-10), но hydrate отдаёт максимум 5 → `acceptance rank hydration incomplete` при объединении >5 (PR 510 §3.3).

## Что сделать (один draft-PR от свежего main)
1. `_evidence_title`: «Автор(ы). Название (год), <locator по-русски: с. N / с. N–M>», только из уже имеющихся полей; отсутствующее поле пропускается; не выдумывать; лимит длины прежний.
2. Новая миграция `sql/kaggle/043_hydrate_window.sql`: `CREATE OR REPLACE` для `rkb_v4.hydrate` и `rkb_v4.hydrate_scoped` — срез `[1:30]` вместо `[1:5]`, остальное тело без изменений.
3. Поднять верхние пределы до 10 (`le=10`, `1 <= top_k <= 10`, предел `QueryResult.evidence`), **значение по умолчанию оставить 3** — его меняем только после замера.
4. Тесты: (а) заголовок содержит автора, год и страницу при наличии полей и деградирует без них; (б) PG17: `acceptance_search`/hydrate возвращает все id при объединении 6–30 (до правки — ошибка `incomplete`); (в) запрос с `top_k=10` возвращает 10 при наличии кандидатов.

## Чего нельзя
- Не менять ранжирование, RRF, лексику, dense, candidate budget, default K, Slack-форматтер (PR 472).
- Не добавлять поля snippet/text в `SearchResult` (совместимость с ChatGPT-коннектором не доказана — PR 510 §7.2).
- Без новых флагов, режимов, кэшей, конфигов.
