## Зачем
RKB — постоянный сервис: пользователь открывает модель, прикладывает книгу и импортирует, без кодового агента рядом. Всё, что модель должна делать при импорте, должно идти от самого сервиса: проверки сервера, ответы инструментов, инструкция. Сейчас правила в инструкции есть (server.py ~552–614, ~1449–1472), но модель их не выполняет: во всём корпусе 2 объявления алиасов, на одной странице Альбинуса — два набора фрагментов (#529).

Уже сделано отдельно: PR 530 — сервер не принимает следующий пакет, пока у предыдущего не применены сущности/истории (раньше они терялись). Не дублировать.

## Что сделать (минимально, без нового импорта и новых инструментов)
1. **Повторная страница (#529, только предотвращение).** `book_ingest(stage)` отклоняет страницу, уже принятую в этой ingestion, если пакет не объявляет явно исправление этой страницы (например, ожидаемая версия/выборка страницы — по предложению в #529). Причина отказа — понятная модели строка: что сделать вместо этого. Ремонт уже задвоенных данных — НЕ в этом задании.
2. **Подсказка следующего шага в ответе инструмента.** В ответе на принятый пакет / status, без новых полей схемы, в `message`/`warnings`:
   - пакет без `entity_candidates` → «на принятых страницах нет сущностей; если в тексте есть места, люди, организации, события — добавь entity_candidates (с историческими немецкими формами как алиасами) в следующий пакет»;
   - в каталоге нет автора или года → «возьми автора/год с титула и исправь через metadata.catalog_update».
3. **Короткий обязательный список в начале инструкции импорта** (5–7 пунктов: один читатель, не переотправлять принятые страницы, сущности и алиасы на каждой странице, каталог с титула, смысловые чанки без чанков-заголовков, ждать `wait` и повторять тот же stage). Длинный текст ниже не раздувать; дубли правил в нём — сократить.

## Критерии готовности
- Тесты: повтор принятой страницы без объявления исправления → отказ с причиной; с объявлением → принят; подсказки появляются только при условии (пустые сущности / пустой автор-год).
- Существующие тесты импорта зелёные; бюджет прод-кода ≤ ~80 строк (без учёта текста инструкции и тестов).
- В PR — дословный новый текст списка и подсказок.
