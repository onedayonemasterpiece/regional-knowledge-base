# Задание: слепое сравнение трёх поисковых политик клиента (решение по языку запроса)

Заказчик: RKB-Ответы (Claude). Методика — [ПМИ PR 519](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/docs/rkb-retrieval-pmi-pilot-20261026/docs/testing/rkb-retrieval-strategy-pmi-20261026.md) §3–§13 (обязательно, особенно §3 «роли и защита от утечки эталона»). Предыдущие данные: PR 519 (RU→RU), [PR 524](https://github.com/onedayonemasterpiece/regional-knowledge-base/pull/524) (RU→DE, DE→RU, не слепой).

## Зачем
Решить, какое правило языка запроса дать модели (ChatGPT, dot, Мира). Сейчас данные противоречат друг другу на малых выборках: смешанная RU+DE строка на немецких книгах 9/10 против 6/10 у русского запроса (один вызов), но на русских книгах теряет второй связанный фрагмент (F01 и его перевод D01 — одно семейство). Нужен слепой опыт.

## Три политики (только эти)
- **V0** — один запрос на языке пользователя.
- **V1** — одна строка: вопрос + немецкий (для русского вопроса) или русский (для немецкого) эквивалент.
- **V4s** — короткая адаптивная инструкция из PR 524 §5 (поиск на языке пользователя → чтение → один шаг по пробелу: соседние страницы / `document_ids` / отдельный запрос на языке источника).

## Роли (разные окна)
1. **«Эталон»** (это окно): составить банк **≥ 30 независимых семейств** — не менее 12 RU→DE (Вихерт 1975, Albinus — только реально принятые страницы, проверить `fetch(source_id,page_start,page_end)`), не менее 10 RU→RU (Гаузе, Трауготт, Маркин, Губин, «Тевтонский орден»), не менее 4 DE→RU, 4 ложные предпосылки; F01–F10 PR 519 и W/A/D PR 524 **не использовать** (они dev). Для каждого семейства — обязательные атомы ответа и минимальные достаточные наборы фрагментов по **принятому тексту**. Опубликовать **только вопросы** (docs-ветка, draft-PR); эталон хранить приватно у себя. Затем написать в общий тред «банк готов» — RKB-Ответы запустит исполнителя.
2. **«Исполнитель-AB»** (отдельное окно, запускает RKB-Ответы): получает только question-only банк; выполняет V0/V1/V4s в случайном порядке по семействам, P=1, сохраняет каждый вызов, выданные id и полученные тексты; в каждой политике формирует **ответ пользователю** (1–4 предложения, источники в конце).
3. **«Эталон» снова, как слепой оценщик**: получает обезличенные пакеты и ответы без меток политики; оценивает полноту доказательств, обоснованность ответа, полноту цитат, ложные утверждения.

## Метрики
По стратам RU→RU / RU→DE / DE→RU: полный доказательный набор в выдаче; обоснованный полный ответ; полнота цитат; число вызовов; время search/fetch (wall и backend). Парные победы/поражения по семействам. Агрегаты — docs-only PR; тексты книг, gold и ответы — приватно.

## Чего нельзя
Не менять код, SQL, live, импорт; не сливать PR; не смешивать с dev-вопросами; не выдавать результат за приёмку при n < 30.

## Решение по итогам (принимает RKB-Ответы)
Политика с лучшим обоснованным ответом при допустимой цене; при равенстве — более простая.
