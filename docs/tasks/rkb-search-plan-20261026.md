## 1. Цель

На любой вопрос модель получает **все фрагменты, нужные для полного ответа, из всех подходящих книг**, с различимыми источниками, и даёт **один ответ** на русском:
- 1–4 предложения;
- источники в конце: автор, книга, год, страница;
- честное «не найдено»;
- расхождения источников показаны.

Время:
- сервер ≤ 1 с на вызов;
- полный ответ в Full MCP ≤ 5–8 с для простого вопроса (уточнить замером).

Корпус двуязычный (RU и DE) и будет расти до сотен книг.

**Принцип разделения труда:** сервер отвечает за полноту и различимость кандидатов, модель — за выбор, дочитывание и рассуждение. Сервер не урезает выдачу «на всякий случай»: модель умеет отделять нужное от лишнего, если ей есть из чего выбирать.

### 2.2 Модель (политика, которую описывает S-g)

1. Разобрать вопрос: предмет, обязательные части ответа, книга, период, возможная неоднозначность.
2. Первый `search`. Язык — по итогам M1.
3. Прочитать тексты выдачи и проверить достаточность:
   - все ли части вопроса закрыты;
   - тот ли это объект или человек;
   - не потеряны ли отрицания и оговорки.
4. Если не хватает, **один шаг по причине пробела**:

| Пробел | Действие |
|---|---|
| Вопрос про конкретную книгу, выдача ушла в другие | `search` с `document_ids` |
| «Этот», «он», обрыв на границе страницы или фрагмента | `fetch` соседних страниц того же источника |
| Нет нужного термина или языка | Отдельный запрос на языке источника или другой формулировкой (не смешанной строкой) |
| Несколько правдоподобных людей или мест | Короткий вопрос пользователю, только с вариантами из найденного |

5. Остановиться при достаточности или по бюджету: **не более 4 вызовов RKB** на вопрос, последовательно.
6. Ответить по рубрике п. 1 и сослаться на **все** фрагменты, на которых держится ответ. Цитаты и выдержки — только по просьбе пользователя.

Логика OR/AND/NOT — по PR 515 §7:
- OR — объединение выдач;
- AND — все свойства у одного объекта;
- отсутствие в выдаче не доказывает NOT;
- XOR как финальный отбор не используется.

### 2.3 Клиентские маршруты

- **Full MCP** (ChatGPT-коннектор, прямой MCP) — политика 2.2 целиком.

## 5. Правила исполнения (против «космолёта»)

1. Одно изменение — один различающий замер. Ранжирование и правила выдачи не сливаются без сравнения на банке.
2. Бюджеты: S2 ≤ ~80 строк production; P1 — текст размером с чеклист PR 531. Превышение — стоп и объяснение в треде.
3. Никаких новых сервисов, таблиц, очередей, режимов и флагов, если пункт прямо их не требует.
4. Один автор на тему. Окно, зависшее больше 30 мин без статуса, перезапускается новым с объявлением в треде. Исключение — импорт одной книги: сначала остановить прежнего читателя.
5. Окна завершают ход статусом `done` или `blocked` с причиной, а не `progress`, и не ждут ответов Slack внутри хода.
6. Слияние — RKB-Opus; установка и live — Шкипер; код пишут окна-исполнители. RKB-Ответы проверяет результат живыми вопросами.
7. Корпус, gold, тексты книг и приватные журналы — не в репозиторий. В docs-PR только агрегаты.
8. Идеи владельца и участников — гипотезы: сначала замер, потом внедрение.

## 6. Метрики (из ПМИ PR 519, считаются по стратам RU→RU / RU→DE / DE→RU / DE→DE / ложная предпосылка)

| Метрика | Что значит |
|---|---|
| Полный набор доказательств в выдаче | В топ-K есть все фрагменты минимального набора из gold |
| Полный обоснованный ответ | Все обязательные атомы, каждый подтверждён прочитанным |
| Полнота цитат | Указанные источники сами по себе подтверждают ответ |
| Ложные утверждения | Утверждения без опоры или с неверной привязкой |
| Честное воздержание | На ложной предпосылке — «не найдено» или исправление предпосылки |
| Вызовы | search + fetch на вопрос |
| Время | Сервер (`backend_elapsed_ms`) и полное у клиента |
