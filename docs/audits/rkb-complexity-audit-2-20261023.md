## 2. Находки и исправления (по убыванию эффекта)

- `server.py` держит два профиля (`legacy` / `kaggle_source`) с десятками `if selected…`. Каждый новый инструмент пишется дважды.
- Кандидаты на удаление, ~12,9 тыс. строк: `supabase_backend` 1836, `story_registry` 2712, `stage_service` 1368, `geo_resolution` 1093, `story_reconcile` 751, `postgres_backend` 523, `sqlite_*`, `indexing`, `graph_discovery`, `street_story_delivery`, `vector_plane`, `e5_*`, `story_ingestion`, `ingestion_enrichment`, `poi_registry_bridge`, `semantic_passages`. Плюс 44 скрипта `scripts/production/{accept,apply,backfill,verify,diagnose,measure,migrate}_*` (~3,4 тыс.) и юниты `ops/regional-knowledge-{indexing,e5,graph-discovery}.service`.
- Связь Kaggle-пути со старым кодом, которую надо разрезать первой: `kaggle_source_owners.py:183` импортирует `supabase_backend._object_store_from_env`; `server.py:31,62,63,957` импортирует `geo_resolution`, `supabase_backend`, `story_registry`.
- Порядок:
  1. GEO из `corpus.sqlite3` (`rkb_geo_*`) перенести в Kaggle.
  2. Проверить импорт-граф от точки входа `kaggle_source` (часть модулей может оказаться общей, например `stage_graph`).
  3. Удалить профиль одним PR с тестами.

**A2. Протокол Dev ↔ ноутбук — пп. 1–5 из 1792761014** (уже выдано). Снимок — решение C (1792762544). Из найденного добавить: `control_spool` 982 и `recovery_journal` 756 строк на Dev дублируют `applied_ops` в PG. Целевое состояние — очередь записей хранится в PG, на Dev её нет.

### B. Импорт

**B1. Модель обязана вернуть 64-символьный `source_image_receipt_sha256` для каждой страницы** (`contracts.py:239`, `kaggle_importer.py:418–438`, `original_intake_controller.py:346–365`). Это SHA-гейт на изображении на критическом пути. Сегодняшний отказ page1 случился ровно на нём. Сервер и так знает, какие страницы выдал этому импорту. Заменить на `(ingestion_id, physical_page_index)` с проверкой «страница выдана». Хэш остаётся только как внутренний ID.

**B2. Цитаты → ссылка на чанк** — контракт 1792763458 (Шкипер/Трасса, выдано).

**B3. SQL026:** exact-key валидаторы и белый список языков. Язык выдан Упрощению, exact-key — Шкиперу вместе с B2.

**B4. Два парсера (текущий + `legacy_parser`) с выбором по хэшу кода** — оставить один текущий.
