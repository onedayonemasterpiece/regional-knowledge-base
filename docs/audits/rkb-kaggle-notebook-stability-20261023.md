## 1. Краткий итог

**Главная системная причина риска:** разные классы ошибок попадают в единый жизненный цикл asyncio FIRST_COMPLETED: событие одной вспомогательной задачи, ошибка конкретного документного задания, ошибка source-команды либо диагностический сбой выходят через task.result() и становятся исключением транспортной сессии; после повторной проверки ранее упавшего task могут завершить весь прогретый runtime. В отличие от них QUERY уже имеет локальную границу исключений, а recovery/original/source_history получили её в PR331. Требуется **один согласованный policy boundary для результата работы** в текущем transport, а не много catch-блоков, новый supervisor или новый status/protocol.

Два P0 класса:
1. **Прямой durable document >512 BGE tokens** допускается 40k-char контрактом, но ResidentEncoder отвергает его ValueError, что может завершить warm worker. **Обычный native book source_command с NativeSourceCompiler уже count-bound до512 и фрагментирует long Story; этот конкретный дефект не является доказанной ошибкой нынешнего compiler.** Механизм прямого document (legacy/editorial) остаётся реальным.
2. **Необязательная read telemetry в worker**: generated bundle сознательно не содержит product_telemetry, однако WSS helper импортирует её после QUERY_RESULT. Первая отдельная export Task выдаёт unhandled exception/теряет телеметрию, а параллельный результат на ветке writer/drop вызывает тот же import в критической Task и может погубить session. Достижимость второй ветки зависит от перекрытия задач; не наблюдалась live.

Следующие P1 классы: необработанный /proc diagnostic exception; generic source_command/receipt-envelope exceptions, остающиеся вне защиты PR331; отсутствие гарантии bounded exit при застрявшем native forward/cleanup; неслитый точный STOP во время bootstrap (PR321). Авторизация, legitimate STOP и неизвестный побочный эффект не маскируются ради uptime.

### P1-C. Ошибка обычной source_command или post-handler receipt сериализации вне PR331 (source)

[scripts/production/bge_wss_transport.py:366-424](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/98d1c672fd7756877e2926a02644a948cbcf9e80/scripts/production/bge_wss_transport.py#L366-L424): source_command перехватывает ApplyUnknown/ApplyExecutionError, recovery family — неожиданные Exception с auth/StaleWriter исключением. Другие unexpected source_command ошибки (например, encoder RuntimeError, неожиданная ошибка helper/import в native materializer) проходят в task.result. Дополнительно построение self.pending и проверка bounded JSON receipt выполняются ПОСЛЕ handler try и могут упасть независимо от уже произошедшего эффекта. Не объявлять каждый такой случай no-effect: результат может быть UNKNOWN. Расширить **тот же самый result/uncertainty boundary** на обе ветви и финализацию envelope, сохранять PermissionError/StaleWriter/CancelledError как fail closed. Дешёвые input-contract ошибки без побочных эффектов можно отличать только если доказаны.

### P1-E. Shutdown может ждать native task бесконечно, даже если lifetime finite (source/hypothesis)

[scripts/production/bge_wss_transport.py:860-891](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/98d1c672fd7756877e2926a02644a948cbcf9e80/scripts/production/bge_wss_transport.py#L860-L891) drain(self.loading,self.read_task,self.encoding), while self.forwards и close_runtime: shield над синхронным torch/blocked native thread не делает поток прерываемым, asyncio.timeout_at(11h) не устанавливает ceiling на finally. Это корректно предотвращает раннее освобождение compute после отмены, но STOP/отзыв не гарантируют prompt process exit при forever-stuck task. Исключить ложную гарантию bounded shutdown; в рамках того же жизненного цикла добавить bounded safe telemetry/операторскую диагностическую точку, а не kill uncommitted operation/supervisor. ## 5. Что НЕ надо чинить повторно

- WSS reconnect bound, generation/nonce, shielded actual forward, per-read deadline, independent QUERY и source pending ACK already exist. Не писать новый retry/recovery framework.
- Native PostgreSQL WAL/transaction, PG role ACL, stale writer, dataset readback/hash, server auth, systemd/TLS/git — другие authority owners; не дублировать гарантию в Kaggle.
- Known v124 import dependency PR329/PR331 закрыт в исходниках; повторный PR по тому же симптому не нужен. Проверить настоящий v125 результат отдельно.
- Прежние latency/history/whole-book barriers из [warm audit](https://github.com/onedayonemasterpiece/regional-knowledge-base/blob/98d1c672fd7756877e2926a02644a948cbcf9e80/docs/reports/rkb-warm-runtime-audit-20261021.md) не объявлять заново P0 stability и не превращать в gate первой страницы.
