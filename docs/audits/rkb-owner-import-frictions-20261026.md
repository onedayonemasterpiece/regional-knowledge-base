# RKB — реестр фактических затруднений модельного импорта (26.10.2026)

**Тип:** диагностический отчёт для triage, не изменение кода и не запрос нового runtime.  
**Срез:** штатный owner-only импорт страниц DjVu через `book_pages → book_ingest(stage) → fetch/status` на действующем Kaggle.  
**Данные:** здесь нет идентификаторов закрытого ingestion/source, сырого текста книги, сканов, внутренних журналов, хешей и приватных receipts. Их можно сверить у владельца по координационному треду без публикации в GitHub.

## Итог и границы фактов

Модельная обработка в том же ingestion продолжается. Исправленный пакет после описанной ниже ошибки успешно попал в обычный путь: `stage` перешёл из `processing` в `staged/continue_pages`, а ограниченный `fetch` прочитал новые source chunks. **Это свидетельство применения и доступности текста, а не подтверждение новой версии Dataset Saved.** Нового `start/reprocess`, повторной отправки ранее принятого материала или изменения backend не было.

## Что **не** считать неисправностями

- `processing / next_action=wait` перед `staged` — штатная асинхронная граница, не причина для повторного `stage`. Не обещать Applied по одному `processing`.
- `APPLIED`, доступность через `fetch` и `Dataset Saved` — разные утверждения. Не называть Saved, пока нет отдельного подтверждения versioned persistence.
- `indexing_status → target_domain_unavailable` вне текущего разрешённого target allowlist **не** свидетельствует о недоступности notebook или импорта; не использовать как stop gate.
- Сомнительная транскрипция скана требует отдельной модельной проверки / `needs_review`; сама по себе не доказывает ошибку сервера и не обосновывает обязательный второй OCR/VLM этап.

## Короткие задачи на разбор

1. **IMP-01 — сначала проверить и починить формирование ошибок pre-dispatch tool-schema**: минимальная redacted диагностика без источникового текста. Это единственный подтверждённый инженерный дефект, заслуживающий непосредственной правки; реализация может лежать вне репозитория RKB.
2. **IMP-02 — закрыть как исправленный клиентский ввод**. Имеющегося ограничения в schema достаточно, нужен корректный payload, не новый backend gate.
3. **IMP-03 — сохранить как ограниченное наблюдение**; эскалировать только при повторном точном read-error и доказанном affected route. Не менять Kaggle runtime без причины.
4. **IMP-04 — учитывать в операторской инструкции без нового состояния.** Перед любым replay сверять exact operation outcome и отсутствие уже принятой страницы.

## Достоверность и ограничения отчёта

Факты получены из успешных и ошибочных вызовов существующих MCP-инструментов в одном owner-authorized сеансе. Специфика клиента при печати исключений может отличаться от логирования на сервере: **наличие полного payload в ответе модели не доказывает сохранение/утечку его во внешние системы**. Никаких воспроизведений на чужих данных, исправлений source/backend/deploy, нового ingestion и live benchmark в рамках подготовки этого отчёта не было. Изменение документации не равнозначно устранению IMP-01/03.
