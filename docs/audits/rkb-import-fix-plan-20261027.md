# RKB: план исправления импорта и переимпорта книг — 27.10.2026

Автор: RKB-Импорт (Claude). Статус: **черновик для второго независимого аудита ChatGPT Pro**; выводы Pro дописываются в §7. Основа — [аудит эффективности](rkb-import-efficiency-audit-20261027.md) (§1–§10, включая первый аудит Pro §9). Код — `main` `2719fae0`. Текстов книг здесь нет. Ничего из плана не запущено.

## 0. Цель и решения владельца, на которые опирается план

Цель: до нового импорта исправить процесс, затем заново импортировать книги, импортированные с дефектами. Импорт — **один, единый для всех форматов** (PDF, DjVu, в будущем веб-страницы): модель через MCP приводит любой источник к одному виду.

Решения владельца (27.10, в дополнение к [owner alignment](../designs/rkb-owner-alignment-20261021.md)):

1. Импорт должен быть прозрачен: каждый шаг покрыт логами, чтобы видеть, куда уходит время.
2. Модель видит страницу в нормальном качестве. Экономить на весе картинок требования **не было**; лимит 256 КиБ — остаток пилота (аудит §10.4).
3. Текстовый слой оригинала полезен как подсказка, но извлекать его должна **сама модель** из приложенного файла, а не сервер детерминистикой. Модели надо подсказать, что текстовый слой есть и его стоит использовать.
4. Начало и конец каждой главы и статьи определяет модель по смыслу. Код границы не выводит (аудит §3.1).
5. Должны извлекаться: дословный текст, геопривязка, личности, факты и даты, истории, иллюстрации, границы глав и статей и всё остальное из аудита §0 и §9.3.
6. Импорт ведёт одно окно ChatGPT от начала до конца книги, один читатель на книгу. Импорт пока планируется только через ChatGPT — это план, а не ограничение.
7. Переимпорт допустим, обратная совместимость не нужна, ремонтных путей быть не должно.

## 2. Как сейчас устроен повторный импорт той же книги (по коду)

- **Повтор той же книги новым окном создаёт новый независимый источник.** Дубли распознаются по `file_id` вложения, а не по содержимому ([`kaggle_importer.py:274-276`](../../src/regional_knowledge/kaggle_importer.py#L274-L276)). Новое окно ChatGPT с тем же файлом — это новый `file_id`, то есть новый `source_id`. Старая версия остаётся в поиске рядом.
- `duplicate_policy=new_revision` для native-импорта отвергается ([`kaggle_importer.py:263`](../../src/regional_knowledge/kaggle_importer.py#L263)). `reprocess` и `rechunk` для завершённой книги всегда отвечают `native_source_revision_upgrade_required` ([`kaggle_importer.py:890-894`](../../src/regional_knowledge/kaggle_importer.py#L890-L894)).
- Снятие источника есть только как внутренняя команда `source.withdraw.v1` ([`control_spool.py:31`](../../src/regional_knowledge/control_spool.py#L31), [`kaggle_domain_bindings.py:45`](../../src/regional_knowledge/kaggle_domain_bindings.py#L45)). В MCP её нет, а как её сейчас вызывает оператор, по коду не установлено.
- Одновременно может идти только один импорт: незавершённая загрузка Mühlpfordt (`acquiring` с 26.10) блокирует новую ([`kaggle_importer.py:285-288`](../../src/regional_knowledge/kaggle_importer.py#L285-L288), сообщение Шкипера 05:13).

**Варианты переимпорта — сравнение со всех сторон** (повтора импорта в системе нет, изобретать его не обязательно):

| Критерий | В1. Снять старую книгу → импортировать заново | В2. Новый источник рядом → проверить → снять старый | В3. Новая ревизия той же книги (reprocess) |
|---|---|---|---|
| Нужен новый механизм | нет: снятие `source.withdraw.v1` уже есть, нужен лишь обычный доступ владельца к нему | нет: то же снятие, только позже | **да**: ревизия 2 в native SQL запрещена ([`kaggle_importer.py:890-894`](../../src/regional_knowledge/kaggle_importer.py#L890-L894)), это большая работа |
| Книга в поиске во время переимпорта | **нет** — пробел на часы или дни (для Albinus при 8–15 стр/ч это часы на сотни страниц) | есть старая версия, новая — по мере принятия страниц | есть старая до переключения |
| Дубли в выдаче | нет | **да**, на переходный период | нет |
| Риск потерять хорошее | старое снято до проверки нового; если новый импорт сорвётся, книги нет | старое снимается только после проверки | минимальный, но ценой сложности |
| Связи (истории, POI, Case, ссылки) | рвутся сразу | рвутся при снятии, есть время перенести | могут сохраниться |
| Нагрузка на людей и агентов | минимальная | проверка + одно снятие | разработка + ревью + миграция |
| Обратимость | снятие — флаг видимости, не стирание данных (проверить, можно ли вернуть) | то же | — |

Предварительная рекомендация: **В1 или В2 в зависимости от книги, В3 не делать.**
- **В1**, если книги мало используются в ответах, у них мало связей (истории, POI, Case) и они короткие. Проще всего, дублей нет.
- **В2** для крупных и часто цитируемых книг (Гаузе, Albinus): поиск не теряет книгу на время переимпорта.
- Мерило выбора — данные А1 и А5: размер, число связей, частота в ответах. Решение по каждой книге — владелец по таблице.

В обоих вариантах:
1. Новое окно ChatGPT, тот же файл, обычный `start` по исправленному процессу.
2. Снятие — обычной командой `source.withdraw.v1`, без нового сервиса. Как её сейчас вызывает оператор и можно ли отменить снятие — проверить (А11).
3. До снятия — список зависимостей старой книги и решение, что пересоздаётся из нового импорта (А5).

## 5. Пробная книга перед массовым переимпортом

Одна небольшая книга с главами, сносками и иллюстрациями, в новом окне по исправленному процессу. Проверка:
- логи по каждой странице (И1);
- выборочный аудит точности с прежними знаменателями;
- границы глав и статей: все от модели;
- выгрузка главы целиком;
- факты, даты, места, личности, истории сохранены;
- время на страницу.

Только после неё — переимпорт остальных по списку А1.

## 6. Чего не делаем

- Никаких новых сервисов, очередей, состояний, флагов, ретраев и проверок сверх перечисленного.
- Не исправляем принятый текст на месте (VETO #529): ошибки старых импортов уходят только с переимпортом.
- Не запускаем второй импорт той же книги параллельно с работающим.
- Не убираем ни одну функцию извлечения (аудит §0, §9.3).
