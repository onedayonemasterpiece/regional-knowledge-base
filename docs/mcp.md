# MCP surface, read models and compatibility

Active target 2026-10-20. [Single handoff](prompts/rkb-scalable-kaggle-implementation-20261019.md), [ingestion](ingestion.md), [rights](rights.md) and [stories](story-registry.md) define behavior. This is a proposed contract, not proof of a deployed WSS/provider. Existing external tool names are retained; changed envelopes are versioned. Old non-GEO IDs do not migrate, but clients are not broken for convenience.

## Goal-oriented surfaces

| Group | Contract |
|---|---|
| `search` / `fetch` | Standard full-profile source evidence search and fetch; stable user-openable evidence references, exact provenance and illustration descriptors. Internal vectors/FTS/storage are not tools. |
| `knowledge_search` | Live-only compact evidence pack in one call: query, max_evidence default 3/max 5 and optional document scope. Target read_query has a correlation request_id, deadline/generation and freshness fence. Existing main_job_id compatibility belongs to its actual legacy/managed dependency contract; it does not make an ephemeral read resumable. No import/admin/graph/proof tool dump in default Live profile. |
| `book_find`, `catalog` | Deterministic bounded title/author lookup (book_find limit≤8); catalog list/find/get and allowed metadata update, keyset cursor/limit≤100. No full-catalog Python sort. |
| `book_ingest`, `book_pages` | One resumable command workflow with start/reprocess/rechunk/stage/validate/finalize/status and small real page ImageContent batches. Source semantic interpretation belongs to calling model. |
| `document_access`, `profile` | Inspect/change permitted grants and small verified identity readback. No client-supplied actor or role as authority. |
| `illustration_fetch`, `catalog_cover`, `source_proof` | Real images with class-specific rights, exact revision/geometry/hash/MIME, per-item continuation. Cover must be a registered real asset, not fabricated. A mostly textual title page is not made public by naming it a cover. |
| Story operations | Existing search/get/history/extract/reconcile/edit/merge/archive/restore, source registration, assertions/evidence/assessment, variants/reviews and publication records. Actual saved body shown by default. |
| Graph/GEO | entity_list, graph_fetch/related/stage, poi_registry search/get/select/create, poi_context and geo queue; bounded source evidence and actual owner receipt. |
| Calendar/measurements | Existing story_calendar, dated claims/history, observation_search/compare and typed edit ops; facts can exist without mandatory Story. |
| Cases/participants/research | Existing compact search/get/history/changes, evidence/contribute/conclusion/support, participants/grants, discussion/export/source needs/drafts/operation status groups. No tool per UI button or second expert MCP. |

Full search retains the compatible `results[{id,title,url}]` projection; fetch retains id/title/text/url/metadata (source/page/provenance/footnotes/illustrations). Rich status and revision fields extend the versioned envelope, not silently replace its type. Stable URL is not an expiring object-store credential or an unbuilt public page.

## Supported direct files and truthful effects

The complete contract is [handoff §§5.5–5.6](prompts/rkb-scalable-kaggle-implementation-20261019.md). Preserve top-level `file` plus `openai/fileParams`, existing book_ingest/reprocess and actual bounded ImageContent. Client-provided download refs are not controller-issued tickets: the server cannot refresh an expired client URL; return source_ref_expired and reattach to the same operation. Opaque attachment IDs and sandbox paths are not network URLs. Direct PUT requires an explicitly supported client capability and successful readback; baseline fileParams remains usable. Large bytes go between supported client hosting/storage and Kaggle, while Dev holds auth/control. Do not silently substitute a Dev byte proxy or ResourceLink for required media.

Tool annotations describe the complete actual method, not one safe action inside a mutating command tool. Preserve appropriate existing names and narrow read/status surfaces; no hidden launch/import/grant/delete from search or status. Server authorization enforces rights independently of hints. Report only server-observable validation/auth/policy/provider/UNKNOWN outcomes. A client-side approval refusal may prevent the call from reaching the server; no-call alone proves neither refusal nor its reason. Reconcile uncertain effects under the same operation ID. Respect prior user authorization without inventing per-page/retry product approvals; never route a denied action through another wrapper to bypass review. Validate real supported ChatGPT/Dot scenarios and non-owner denials (DBG-11–13); do not suppress features to reduce approvals.

## Three execution modes, one authority

| Mode | Admission and transport | Durability and completion |
|---|---|---|
| `read_query` | Bounded RAM permit from the existing admission authority; `QUERY`, `QUERY_RESULT`, `CANCEL_QUERY` on the existing notebook WSS. Ready work dispatches immediately. | No per-read durable queue row, fsync, remote intake/seal, RESUME or resultSaved. request_id correlates this attempt; it is not a saved-result handle. Disconnect/deadline/cancel ends the attempt; an old-generation result is dropped. |
| `durable_question/request` | Existing person/dialog sequence, fair admission, exact input and result lifecycle. Nested reads inherit the managed context and do not create another human request. | Accepted requires exact remotely verified intake; saved/result-ready requires exact durable outcome. Resume and result/hash/native ACK refer to that same request. |
| `mutation/provider-effect` | Existing scoped command/operation, immutable intent, preconditions, generation and effect fence. | Preserve exact remote intake, domain commit, receipts, UNKNOWN reconciliation and delivery order. Cancellation of a read/transport cannot cancel or recreate an accepted effect. |

Mode comes from the trusted operation contract, not a caller's claim that a write is a read. Dot→tools and Mira→tools are independent smart routes using this authority. Mira's physical path is PH typed provider→existing DevCoveer auth/admission→the authenticated WSS initiated by the notebook; no additional Dot turn, HTTP self-call, second WSS relay or public notebook listener. Encoding, indexed SQL retrieval and bounded hydration form one typed Kaggle query; 1024-float query vectors stay there.

## Search and read contracts

Query all active accepted book text/bibliography without per-book owner ACL. Request document/article scope, current revision/withdrawal and private derived content still apply. PostgreSQL does scope/indexed ranking/batched hydration; no list of all document IDs sent to another vector service. Dev sends compact verified identity/scope and authority epochs. Kaggle must satisfy them and batch-check current eligibility of returned top-K dependencies; Dev rejects revoked or stale-generation responses before delivery. Cache entries never grant access. BGE only on Kaggle, bounded lexical/alias complement, common 2000 ms evidence deadline. E5 fallback is not a target mode.

The delivery policy check covers each item's full source/variant/grant dependencies, including cross-book text and bibliography. A matching revocation drops the whole affected item and its display/continuation fields; removing only a citation cannot sanitize its text. Remaining evidence is explicitly `degraded/evidence_withdrawn`, including when zero items remain, never empty success. Unrelated eligible reads continue. Missing provenance, compacted policy-delta history or an unproven current scope fails closed for the affected scope/result; a fresh cursor alone is not authorization. The remote-durable access barrier and the separate pending PG withdrawal/public purge follow [handoff §§6, 10.1](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Warm backend p95≤1000 ms, MCP p95≤1500 ms and hard 2000 ms remain protected. A cold/unavailable dependency yields an explicit bounded status and any honestly labelled eligible lexical evidence; read_query does not promise eventual delivery, reserve a durable question or replay on reconnect. A managed request instead preserves its existing dependency checkpoint and result lifecycle. Empty preliminary hits are not a definitive absence. Index vector counts do not prove loaded worker readiness.

Every v2 response identifies the actual data/projection freshness and whether min_data_seq is satisfied. Read after a saved change must use sufficiently fresh data or explicitly report that it cannot. The existing controller indexes unresolved mutations by canonical person and typed resource/scope dependencies across Dot, Mira and personal MCP. At actual read start and delivery, an intersecting pending/UNKNOWN write returns `prior_write_pending` with observed freshness; do not claim latest state, definitive absence or a successful write. Shared-resource changes affect all relevant readers, not only the author or dialog. Typed dependency classes keep an unrelated private-draft UNKNOWN from blocking accepted-book search; unproven independence is treated as dependency. This does not create an UNKNOWN read record. Durable per-dialog order remains a separate rule; see [handoff §§5.2, 10.2](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Live returns small evidence and image descriptors initially; request image explicitly through allowed progressive client capability. Source quote/attribution/calendars/uncertainty survive voice. Ordinary stories read the saved basic body or saved adaptation and put bibliography on screen. No LLM generation during `get` to conceal missing narrative.

`story_get` default returns exact Variant.body/ref/revision/hash with bibliography separately. A candidate without body returns body=null plus availability/reason. Search distinguishes ready narrative from dossier and gives a full short body or clearly marked excerpt + exact reference/cursor. Read-export follows Story read scope; publish-export additionally requires approval/capability. Compact mode cannot silently fall back to summary. Private author drafts remain private even though imported shared body may be an editorial draft.

## PH typed result v2 and compatibility

At PH main [940864a, regional_knowledge.py](https://github.com/onedayonemasterpiece/projects-hub/blob/940864ae70bbcf334610712fa0b33cf2f781d3d3/src/projects_hub/regional_knowledge.py), the provider is an injected interface and the strict normalizer accepts only `evidence` and `mode`. Implement and verify a versioned v2 typed result carrying explicit status, execution mode/request correlation, generation, freshness/min_data_seq satisfaction and bounded continuation/detail refs alongside evidence. A pagination/detail cursor does not imply durable RESUME. Durable result/ACK fields are present only for the durable mode that owns them.

The v1 adapter emits success only when the complete meaning is representable by the old evidence/mode contract. An unrepresentable pending, prior_write_pending, stale or unavailable result uses the existing unavailable/error boundary; never disguise it as empty hybrid success or silently drop required freshness. Source attribution, actual saved story body/ref, uncertainty and relevant details survive adaptation. Validate the typed payload at trust boundaries without repeated JSON repack or a second search/hydrate call.

PH preserves exact ordered evidence/context refs under `(session, turn_generation, tool_call_id)` in its existing private tool/utterance store, tied to the committed turn and disposition. For ephemeral reads this checkpoint is asynchronous and does not delay the answer. A crash before it commits yields explicit `context_gap/evidence_context_unavailable`; a new search or nearby transcript cannot stand in for the old refs. Continuation/context refs are not capabilities and must pass current authorization on reuse. This is dialog recovery state, separate from lossy telemetry and from a durable RKB result/ACK; see [handoff §10.4](prompts/rkb-scalable-kaggle-implementation-20261019.md).

Preserve PH limits: query≤1000 characters; max_evidence default 3/max 5; each text≤8000 characters and all evidence text≤24000; each metadata object≤12000 encoded bytes, depth≤5, container width≤64 and existing per-string/key limits. Keep bounded filters and transport bytes. The pinned BGE tokenizer checks the complete input≤512 tokens; character limits are not token proof. Oversize input is explicitly rejected/refined, never silently truncated. Oversize result uses a bounded clearly labelled excerpt/detail continuation; it does not masquerade as the full saved text. Initial QUERY_RESULT carries image descriptors, not image/PDF bytes. Progressive authorized image/proof operations retain native ImageContent and their own status.

## Ingestion boundaries

New-source top-level `file` keeps `_meta["openai/fileParams"]`. PDF/DjVu belongs to start/reprocess; bounded stage JSON is a separate transport of the same typed data. New source default4/max8 page ImageContent, exact source/revision, region/span hashes, visual review, semantic completeness and BGE tokenizer gates remain. Full [ingestion contract](ingestion.md) records block/page continuations and limits; do not equate preview with full source reading.

Every ingestion response exposes next_action and real source/index/knowledge progress. Facts/dates/entities must survive zero stories. Sufficient episode saves a default basic narrative and verifies normal readback. Source activation and persisted research/compose frontier are atomic; new shared source does not auto-publish or confer human endorsement.

Expose text_search_ready independently from archive_ready within the existing run. Searchable verified text must not wait for unrelated archive copying; proof/original access still requires the actual available verified asset. This separation creates neither another import controller nor extra Kaggle runs beyond the authorized capacity/session cap.

Accepted-source extraction uses existing story_extract/corpus_read checkpoints and the same facts/body contract without reimport. Rechunk only changes derived passages of verified unchanged accepted source; catalog updates do not change source/evidence. Owner personal-route restrictions apply even if a Slack bot was invoked by owner.

## Graph and structured knowledge

Stage bounded graph bundle≤32 nodes/64 evidenced directed relations. Node kinds person/organization/event/historical_thread/poi_ref; alias/mention/type/temporal context determine candidate identity, not an automatic name merge. graph_fetch returns one entity with at most20 one-hop relations and paged aliases/mentions. graph_related uses same retrieval and pending envelope. graph_stage accepts source-grounded new facts/alias and optional discovery request, never a full graph dump.

Source-place can exist without coordinates/Street Story ID. Verify selected/created physical POI through its owner; graph discovery hits are not automatically facts/identity. Existing external canonical aliases come from owner projection, not caller injection. Public POI does not expose private drafts/attachments linked to it.

`story_calendar(month,day,calendar,limit,cursor)` selects current exact day-level event datings, not publication dates/approximate years. Preserve original_date_text, calendar/precision/date_role, competing datings and explicit supersession. Do not silently convert Julian/Gregorian/unspecified. Existing event_dates_page/history and record_event_date retain exact source evidence.

RecordObservation keeps original numeral, exact decimal, metric_key/unit_code, subject/period/method/precision and evidence. Existing observations_page/history, story_observation_search and story_observation_compare stay bounded; compare refuses unverified arithmetic across mismatched subjects/periods/methods. The new storage path permits these facts outside a Story without deleting the old compatible operations.

## Proof and artifacts

Illustration returns a genuine canonical accepted figure crop publicly, printed caption separate from labelled model observation. Stripe/page quote proof requires owner/demo/expert/local_historian capability, current scope and authorized audience. Full original download is separate. Trusted artifact class/geometry and separate cache identities prevent full-page-as-illustration bypass.

Keep native PDF quads first, same-page multi-region and page-by-page multi-page quotes; explicit page requires quote scoped there. Native matching may tolerate existing bounded adjacent punctuation without altering internal text. Scans/DjVu use the existing configured Flash-Lite localization/independent strip-read adapter where enabled, not image generation or another general ingestion LLM. Preserve current bounded policy:25s provider call timeout,≤4M pixels,4096 output tokens,≤2 calls/page; async proof must not hold the2s evidence search. Second visual read does not receive expected quote. Verify convex in-page bounds, order/stripe area and text equivalence; confidence/echo alone cannot authorize exact proof.

Source SHA/revision/physical page/render hash/dimensions/transform/task generation bind locator. Pin preview until terminal callback; changed pixels require new locator. Authorize both quote_proof and internal source_archive purpose access without owner impersonation. On cache hits/delayed output recheck grants and withdrawal. Ready/pending/denied/unavailable/failed per item; retain operation ID through ArchiveReadPending. Return actual ImageContent and actual MIME, with distinct source/display/provider/delivery hashes.

## Durable request envelopes and acceptance

For durable_question/request and mutation/provider-effect, transport received/pending, remote durable accepted, domain saved and delivered/result-hash ACK are different. Shared person/dialog sequence, fair admission, current request generation and service scope cannot be bypassed by an explicit ID. Read_query uses the same authority's RAM permits without these persistence promises; durable question/mutation preserves exact payload/outcome under [storage](storage.md).

Read telemetry is a separate bounded buffer with a batched sink outside the queue SQLite write lock and outside the response path. Record safe IDs/refs, sizes and stage durations, not query/evidence/private-draft bodies or credentials; drop-on-full with a counter is allowed. PH `_mark_semantic_observed`, utterance recovery/checkpoints and accepted-request/effect records are domain state, not disposable logs. Measure PH tool-lock wait separately from execution duration. Bounded parallel reads may be admitted, but removing all tool locks or allowing effects to bypass ordering is not an optimization.

Test real clients with a non-owner, direct forbidden calls, revoked link/grant, cross-route stale callback, private draft history, actual body/image readback and reconnect result ACK. Endpoint existence, cached catalog visibility or green unit tests alone do not establish client support.

Verified demo/expert/local_historian assignment materializes the existing scan_proof_read policy grant with audit and category revision; demo expiry is inherited. Claimed categories grant nothing. Current capability/scope is checked at render time; explicit revocation is not recreated on read, and removing a category withdraws its policy-derived grant. No new IAM or per-image approval.
