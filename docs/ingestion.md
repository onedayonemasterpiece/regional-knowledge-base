# Импорт: source fidelity, знания и сохранённые рассказы

Уточнения владельца 21.10.2026: [owner alignment](designs/rkb-owner-alignment-20261021.md). Ровно один active owner-only import, включая resume/reprocess; reads продолжаются. Все рабочие stages/graph, проверка complete BGE input и установка document vectors выполняются в Kaggle/PG. Dev не хранит второй рабочий книжный graph. Целевой Telegram archive — direct Telethon, presence-only media verification; Dataset primary и weekly Yandex backup, без ложного Saved до доказанной внешней сохранности.

Контракт20.10.2026 для target PostgreSQL/pgvector+BGE в Kaggle. [Единое задание](prompts/rkb-scalable-kaggle-implementation-20261019.md) содержит полный prompt, recovery и gates. Смена документа не означает выполненный импорт.

## Обычный пользовательский сценарий

«Добавь эту книгу» + PDF/DjVu запускает `book_ingest(start)`; модель читает реально доступные ей страницы и продолжает stage → validate → finalize/status. Если пиксели уже доступны клиенту, повторный backend render не нужен; `book_pages` используется по запросу для отсутствующих страниц/продолжения. Пользователь не обязан знать UUID, cursor или duplicate_policy. Для уже принятой **в новой системе** книги: `book_find` (до8 результатов) → `reprocess(document_id)` по проверенному оригиналу. Несколько правдоподобных изданий требуют выбора по названию/автору/году, а не угадывания. Новый cutover всегда fresh MCP import: old non-GEO content не переносится.

Идентичность оригинала — SHA-256, издание, формат и physical page count, не имя файла. Повтор того же attachment/reprocess idempotent, concurrent start не создаёт дубли. Один SHA не сливает разные явно выбранные logical documents. Нормальный повтор возобновляет pending revision; explicit new_revision создаёт новую только по осознанному намерению, со своим stable key.

Original archive pending означает wait/resume соответствующей archive-операции; её успех — доступный ожидаемый Telegram media locator, не mandatory download/hash comparison. Если verified archive действительно недоступен, owner может приложить тот же оригинал к reprocess: сервер проверяет SHA/format/page count до открытия revision, резервирует staging capacity и восстанавливает только private source bytes. Иное издание не принимается как тот же источник. Предыдущая active revision продолжает работать до принятия замены.

Ожидание относится к конкретной операции с ещё недоступными bytes. Готовый текстовый поиск по уже принятому корпусу не ждёт Telegram preflight, оригинала или proof. Text/archive/proof readiness различаются; source-fidelity и обязательные archive/recovery gates самого импорта этим не обходятся.

## Передача исходника без Dev bulk proxy

Для image-only DjVu `book_pages` использует существующий DjVuLibre из проверенного native bundle в Kaggle. Приём и проверка оригинала ещё не означают готовность пикселей: рендерится только запрошенная физическая страница, а пустой native text требует визуального чтения моделью. Ambient decoder и локальный OCR не подменяют этот путь. DjVu с текстовым слоем или неподдержанной ориентацией остаётся явно недоступным, пока адаптер не умеет сохранять соответствующий текст и преобразование координат.

Полный контракт — [handoff§5.5](prompts/rkb-scalable-kaggle-implementation-20261019.md). Существующие book_ingest и top-level file/openai/fileParams сохраняются. Разрешённый client download URL читает непосредственно Kaggle; sandbox/opaque ID требует настоящего supported adapter. Это внешний reference, который controller не умеет перевыпускать: source_ref_expired возвращает reattach той же pending operation. Reprocess работает с verified durable original. Direct client PUT включается только по поддержанной capability/readback; при её отсутствии baseline fileParams не исчезает.

Upload attempts имеют разные immutable keys и один transfer ID; exact provider readback/size/full hash precede atomic first-verified binding. Lost ACK не создаёт второй import. Private visibility, URL/redirect/archive/byte bounds и защита notebook outputs обязательны. Temporary staging не удаляется до durable archive/recovery refs; новый Kaggle Dataset не нужен каждой книге/порции. Page ImageContent и source fidelity остаются прежними.

## Чтение и ограниченный stage

`book_pages` возвращает реальные MCP ImageContent и native block previews: default4, maximum8 страниц. Native extraction — необязательная помощь, не OCR/semantic authority и не gate совпадения с транскрипцией модели. Calling model визуально читает source; backend не вводит скрытый OCR/VLM/LLM, полный предварительный обход книги или обязательное архивирование всех page derivatives.

Native block metadata сохраняет original_length/offset/end/truncated/continuation. Block continuation выдаёт до1000 символов и соответствующую страницу; repeated cursor возвращает тот же диапазон. Finish block cursor до перехода к следующему; `blocks_continuation` раскрывает блоки за preview cap80. Page preview до24000 символов не доказывает полноту. Empty native text может сопровождать содержательную scan page. CID/ToUnicode encoding_notice требует сверки с изображением; отсутствие notice не отменяет её.

Versioned opt-in клиента может избежать повторной передачи того же изображения: первая порция всегда содержит actual ImageContent, дальнейшие native continuations той же страницы **в том же живом visual context** могут возвращать offsets + exact source/page/render hash reference. Это не урезает текст или image resolution. Новый чат/context, потеря картинки, неизвестный context или изменение render требуют снова actual ImageContent до визуального review; одна сохранённая hash/reference не доказывает, что модель видит страницу. Без согласованной поддержки клиент получает прежний ответ с изображением на continuation. Cursor/full-coverage, все figures/captions и visual-review requirements остаются прежними.

Source regions ограничены8000 символами с правильным reading order. Continuation portion не становится автоматически semantic region. Каждая новая/изменённая страница, включая image-only, имеет visual_reviewed + source_review_note; unreviewed/preview/full_native не проходят как визуально проверенные. Сервер проверяет attestation/schema/coverage, но не притворяется независимым читателем книги.

Stage использует local region_key/illustration_key и стабильные server IDs, exact source revision, typed page geometry/relations. Semantic chunk text компилируется из accepted region/span refs, не из свободного model retelling. Сохраняются headings/body/captions/footnotes/tables/marginalia; смысловой заголовок предшествует связанному тексту через упорядоченные region_refs/span_refs того же passage, без привязки ко всем passages и без отдельного чанка только ради покрытия; running header/page numbers сохраняют provenance, но не требуют самостоятельного passage. Для spans: Unicode codepoint offsets, whole-region SHA, valid ranges, word boundaries, отсутствие overlaps и пропущенного non-whitespace source content. Связные продолжения соединяются через страницы; layout не определяет embedding units.

Цель — около256 BGE tokens, strict maximum512 **полного augmented input с prefix** по pinned BGE tokenizer. Число символов — диагностический ориентир, не tokenizer. E5 gate удалён. Oversize input требует корректного нового semantic split/контекста, не silent truncate; footnote с реальным контекстом тоже не теряется.

Inline stage или один UTF-8 JSON file — два транспорта одной schema, не два workflow. Существующий file envelope: ≤1MiB, ≤8 страниц, ≤100 chunks, ≤12 episode candidates; не смешивать file с inline/metadata и не принимать PDF в stage. Если findings/body не помещаются, продолжить bounded batch, а не обрезать/терять их. Проверить job rights до download; сохранить package SHA. Validation errors возвращают ≤8 paths/types без private values; unknown field names маскируются. Новый facts/body contract versioned, клиентские имена не выдаются за уже реализованные.

## Логические границы статей и глав для будущего PDF-экспорта

[Решение владельца 26.10.2026](designs/rkb-source-unit-pdf-and-audio-20261026.md): границы логической единицы определяет **та же модель, которая читает страницы через MCP при импорте**, а не отдельная модель по требованию читателя. Вместе с обычным stage модель фиксирует подтверждённые начало/конец статьи, главы или раздела через существующие page/region/span references; единица может оставаться открытой до следующего пакета либо проверенного конца источника. Использовать текущую идентичность catalog article, где она уже есть; не создавать второй корпус или независимый экспортный граф.

Выгрузка «полный текст главы/статьи в PDF» — **новая генерация документа из принятого дословного текста регионов** внутри этих границ, а не нарезка оригинала. Поэтому она одинакова для любых форматов источника (PDF, DjVu и др.) и зависит только от точности логических границ, поставленных при импорте. Начало и конец каждой единицы определяет модель по смыслу текста; код границы не выводит, а только проверяет и хранит точные ссылки. Статус 27.10.2026: приём границ в stage и их чтение (P0.A, PR 552/556) работают в runtime и проверены живьём; генератор PDF (PR 554) слит, выдача пользователю ещё не подключена. Отсутствие уверенной границы **не блокирует принятие очередной страницы и её поиск**: единица остаётся незавершённой и пока недоступной для полного PDF. Принятый текст не восстанавливается по BGE чанкам; для старых источников без границ структурное уточнение идёт через обычный owner-only import/reprocess, не через модельный запрос в момент экспорта. Новая функция не изменяет текущие защищённые performance/source-fidelity требования.

## Один смысловой проход

В том же чтении сохранить claims/evidence, даты/calendars/precision/date_role, людей/роли, организации, события, historical threads, места/топонимы, observations с decimal/unit/subject/period/method, captions/figures и disagreement candidates. `knowledge_reviewed=true` означает рассмотренные категории с честными пустыми результатами, не100% recall. Ни один полезный факт не требует фиктивного Story.

Результат routing: fact, attach to dossier, new episode, continuation. Эпизод может пересекать windows/pages. Identity проверяется по source/subject/time/place, не title/vector alone. Достаточный эпизод **обязан породить сохранённый basic Variant.body** и exact default revision: обычно2–6 связанных предложений, одна мысль, развитие, известный итог либо честная граница знания. Bibliography отдельно. Summary, похвала потенциала или seed без variant не завершает story extraction. Полный prompt/read API в [story registry](story-registry.md) и handoff§8.

Недостаточный материал остаётся facts + concrete gap/needs_context + persisted continuation. No story quota, forced conflict/emotions/causality or mandatory happy ending. Title «Как/Почему» должен отвечаться body. Легенда/воспоминание/спор сохраняют нужную атрибуцию; номер примечания/страницы не становится обычной первой фразой рассказа. Ни один импорт не присваивает human support или publish_ready.

Существующий entity bundle ограничен32 nodes/64 evidenced relations. Person/organization/event/historical_thread/poi_ref, directed relations и exact quotes сохраняются; existing entity_id выбран по проверке identity. Entity_refs не создаёт фиктивные mentions. Literal date/number должен присутствовать в соответствующем evidence. Новая source revision не стирает параллельные подтверждённые POI/map refs или человеческую редактуру.

## Активация и продолжение

Source revision activation, accepted facts/подготовленные bodies и reachable research frontier фиксируются атомарно в PG. Сначала готовить staging/projections; activation меняет компактный pointer, не переписывает все активные passages. Body+default ref+source dependencies+receipt атомарны, после commit ordinary readback проверяет exact body/revision/hash. Exact accepted model payload удалённо закреплён до application; retry/recovery не вызывает модель заново.

Document indexing выполняется рядом с PG/BGE на Kaggle: exact minimal search material читается локально, bounded vector batch устанавливается там же с revision/hash checks. Dev не служит промежуточным хранилищем query/document vectors. Уже принятые payloads и точные outcomes остаются remotely durable; сокращение network copies не меняет accepted/Saved или ordinary body readback. Импорт уступает измеренный search reserve на существующих safe batch boundaries, не ждёт заполнения query batch и не прерывается посреди commit.

Research frontier один для story reconcile, сопоставления источников/cases, открытых source needs и POI enrichment. Не два полных N² scans. Активация не ждёт будущего экспертного консенсуса, идеальной карты или Street Story; downstream effects живут в существующем outbox. Pending compose/context явно виден. Индекс/source acceptance/research completeness/publication approval — разные состояния.

Ошибочное optional metadata item получает needs_review с исходным payload/reason и сохранёнными корректными facts. Unexpected transactional error не оставляет частично перезаписанный candidate checkpoint. Исправление metadata-only тем же stage/checkpoint не меняет source/chunks/vectors. Repeated activation не создаёт новые dates/Story/Variant/cases; superseded source не переписывает approved/human variants.

Status содержит compact next_action, actual revision, indexing/projection lag, coverage и не более10 нуждающихся в доработке findings. `pass_completed` означает выполненный заявленный проход, не полноту знаний. `next_action=done` не маскирует unfinished knowledge extraction. Status использует indexed bounded reads, не загружает полный GraphBundle корпуса. Блокер на одной книге не держит unrelated imports.

## Работа с уже принятым новым источником

`story_extract(start/claim/stage)` с exact active revision и `corpus_read` продолжает incomplete semantic pass без нового PDF import. Existing batch default20 source chunks, ≤10 grounded candidates/stage, scope/lease/expected job revision и exact source regions проверяются в той же transaction. Boundary beyond batch даёт continuation, а не раздробленный episode. Zero candidates допустим с сохранёнными facts/coverage. Использовать тот же basic-body contract, не прежний seed-only path. Unverified editorial seeds разрешены как явно помеченные leads, не source-backed extraction.

`rechunk` — только derived passages на уже принятом неизменном новом source с `accepted_reuse`. Сервер проверяет source SHA, complete accepted review graph, pages/regions/geometry/reading order/figures/captions/relations; статус не self-certified. Missing original review evidence требует нового visual review, а не переименования. Text-only verified rechunk может обходиться без PDF; illustrated final recrop требует verified original. `reprocess` нужен для нового чтения/разметки источника. [Semantic passage contract](operations/source-backed-semantic-passages.md).

Accepted source pages/evidence/history остаются immutable. Catalog.update whitelist + expected_revision исправляет title/authors/year/language без изменения identity/chunks/ACL. Issue/article component имеет verified parent/region boundaries, не overlapping ranges и не split chunk; partial issue не выдаётся за полный номер. См. [corrections](operations/import-finalization-corrections.md).

## Приёмка

Последовательные fresh A→B/B→A; competing start/resume подтверждают единственный owner import lease и конкурентные чтения, не несколько импортов; retry stage/finalize/extract/body save; отсутствие эпизода при полной сохранности фактов;Cross-page episode; настоящие body после restart через get/search/voice; exact proof и archive continuation; metadata repair без переписывания source; withdrawal/read-after-write; per-book natural/paraphrased/cross-language retrieval на точной revision. Затем protected scale100books/100kchunks, BGE Hit@5/10, latency и80/90% headroom. Одни vectors-ready/успешный finalize не являются массовой готовностью.

Opt-in image continuation дополнительно проверяется в одном live context, после потери image/context, в новом чате и после изменения render. Все native offsets/blocks и source facts совпадают с полным контрактом; новый context снова получает реальные pixels. Проверить, что Telegram/proof outage не блокирует готовый text search во время imports, без увеличения разрешённого числа Kaggle runs.
