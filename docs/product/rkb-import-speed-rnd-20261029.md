# RKB — исследование скорости импорта (R&D), 29.10.2026

Цель владельца: 100 книг меньше чем за месяц. Это ~20–25 тыс. страниц, около **30 стр/ч круглосуточно**. Без потери качества и функциональности: дословный текст, границы статей, сущности.

## Где сейчас время (Albinus, плотный словарь, ~7 тыс. символов на разворот)

- Чистое чтение одного окна ChatGPT — **18–20 стр/ч** (~180–200 с на разворот). Сервер: stage→apply ~0,8 с, это не узкое место.
- На разворот читатель выдаёт ~30–40 регионов и ~25–35 смысловых фрагментов, плюс границы статей, сущности, факты, истории. Payload — около **24 КБ JSON** (p115).
- Помимо чтения на каждой странице: **два сообщения в Slack** (STARTING_STAGE и APPLIED — 60 из 101 последних сообщений общего треда), `status` и проверочный `fetch`. Это вызовы инструментов и генерация текста, которые не добавляют продукту ничего.
- Режим рассуждения окна — «Очень высокий» (Extra High).

## Гипотезы, по убыванию ожидаемого выигрыша на единицу усилий

| # | Гипотеза | Ожидаемо | Как проверить | Исполнитель |
|---|---|---|---|---|
| E1 | Убрать per-page сообщения в Slack и проверочный `fetch`: отчёт раз в ~10 страниц или при блокере, `status` — только по `next_action` | +15–25% | 10 страниц до и после, с/стр по журналу stage | RKB-Импорт |
| E2 | Режим рассуждения High вместо Extra High для транскрипции | ×1,3–2 | A/B по 10 разворотов; с/стр и ошибки дословности против повторной сверки с изображением | RKB-Импорт, оценка — RKB-Ответы |
| E3 | Обогащение (сущности, факты, истории, POI) — отдельным вторым окном по уже принятым страницам, параллельно чтению; инструкция уже допускает pending-обогащение | +20–40% у читателя | Проверить по коду, что обогащение принимается для принятых страниц (`graph_stage`) без перечитывания текста; затем замер | Opus — код, RKB-Импорт — замер |
| E4 | 2 разворота в одном stage (лимит 4): меньше циклов status/wait | +5–10% | A/B по 10 разворотов | RKB-Импорт |
| E5 | Черновик OCR в Kaggle (для книг с хорошей печатью), модель сверяет с изображением и исправляет вместо транскрипции с нуля | неизвестно, потенциально ×2 | Сначала исследование: качество OCR на 3 книгах (антиква, фрактура), без кода | окно-исследователь |
| E6 | Параллельные книги: второй и третий читатель на разных книгах | ×2–3 пропускной способности | После установки 620 (нет отказа по времени) и параллельных чтений поиска; замер поиска 8/8 под двумя импортами | RKB-Импорт; поиск — Шкипер/RKB-Ответы |

Правило для всех опытов: качество проверяется, а не предполагается. Дословность — повторной сверкой выборки с изображением; границы статей — по `book_find(view=units)`; поиск — пачкой вопросов RKB-Ответы.
